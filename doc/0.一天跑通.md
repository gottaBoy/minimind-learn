# 一天跑通 MiniMind

本篇负责按命令完成训练闭环。需要逐步理解每个对象时，配合 [学习路线](0.学习路线.md)、[概念速查](0.概念速查.md) 和各章的 CPU 小实验；不用把一天命令全部执行完才开始理解源码。

验证日期：2026-11-21。当前设备为 Linux ARM64、Python 3.12.3、NVIDIA GB10，驱动为 580.173.02。已经用系统已有的 `uv 0.9.7` 配好项目内 `.venv`，可以直接从第 2 节开始。本次实际运行版本为 PyTorch `2.14.0+cu130`、torchvision `0.29.0`、Transformers `4.57.1`。

当天的验收目标是完成 tokenizer 验证、预训练、SFT、LoRA、权重保存、恢复和推理。几条 demo 数据只能证明代码可用，不能证明模型具备聊天能力。PPO/GRPO、蒸馏和 VLM 还需要奖励模型、教师模型或视觉编码器，放在这个闭环之后。

| 时间预算（按下载和吞吐调整） | 做什么 | 验收 |
| --- | --- | --- |
| 第 0-1 小时 | 配环境、验证 GPU 和 tokenizer | CUDA 可用，tokenizer 往返一致 |
| 第 1-2 小时 | demo 预训练、SFT、LoRA、推理 | loss 有限，权重能重新加载 |
| 第 2-4 小时 | 真实数据子集、限步训练和恢复 | 最后一步保存，恢复从正确 batch 开始 |
| 第 4-8 小时 | 扩大子集和步数，比较训练前后输出 | 记录训练速度、loss 和固定问题的输出 |
| 剩余时间 | 调整参数、阅读对应源码 | 再选择一个进阶训练阶段 |

## 1. 安装环境

在项目根目录执行：

```bash
cd /home/my/workspace/llm/minimind-learn
uv venv .venv --python /usr/bin/python3
UV_CACHE_DIR="$PWD/.uv-cache" \
  uv pip install --python .venv/bin/python \
  --index-url https://pypi.org/simple \
  -r requirements-aarch64.lock
```

首次安装会下载 PyTorch 和 CUDA 运行库，占用数 GB 磁盘空间。`UV_CACHE_DIR` 使用项目内缓存，避免系统缓存目录权限问题。`.txt` 列出 6 个直接依赖，`.lock` 固定实际安装的传递依赖；训练所需运行库由 wheel 提供，使用当前驱动即可。

`pixi.toml` 和重新生成的 `pixi.lock` 也已覆盖 ARM64/x86_64。锁文件由项目内 `.tools/pixi`（0.84.2）解析生成，实际训练验证使用 `.venv`；两条环境路线选一条即可。Pixi 用户可执行 `pixi install --locked`、`pixi run smoke`、`pixi run demo`。需要实验记录时使用 `pixi run -e tracking ...`，uv 用户单独安装 `swanlab==0.6.8`。

检查 GPU：

```bash
UV_CACHE_DIR="$PWD/.uv-cache" .venv/bin/python - <<'PY'
import torch
print("torch:", torch.__version__)
print("cuda available:", torch.cuda.is_available())
print("cuda runtime:", torch.version.cuda)
if torch.cuda.is_available():
    print("device:", torch.cuda.get_device_name(0))
PY
```

如果机器没有 CUDA，后面的命令把 `--device cuda` 改成 `--device cpu`；CPU 只建议做 smoke test。

## 2. 先做 1 分钟 smoke test

它会检查 tokenizer、模型前向、反向传播、缓存与完整前向的数值一致性和 `generate()`：

```bash
.venv/bin/python scripts/smoke_test.py
.venv/bin/python scripts/train_tokenizer.py
.venv/bin/python -m unittest discover -s tests -v
```

预期能看到 `cuda_available=True`、`logits_shape=(1, 9, 6400)`、一行 `generated=...` 和 `backward and KV cache checks passed`。测试目前共 18 项。生成内容随机是正常的，因为 smoke test 使用随机初始化权重。

下一步按 [逐步调试教程](0.逐步调试.md) 观察一个 batch 的 token、logits、loss、梯度和参数更新。

若要练习 tokenizer 训练，可保存到独立目录：

```bash
.venv/bin/python scripts/train_tokenizer.py --train \
  --data_path dataset/demo_pretrain.jsonl \
  --output_dir out/tokenizer_demo --vocab_size 512
```

demo 语料很少，实际词表可能小于目标大小。新 tokenizer 不能直接配已有权重使用；主训练流程继续使用仓库自带的 `model/`。

## 3. 用仓库自带小数据完成训练和推理

这一步不需要下载大数据：

```bash
DEVICE=cuda ./trainer/run.sh
```

脚本依次执行：

1. `scripts/smoke_test.py`
2. 6 条样本、1 个 epoch 的小型预训练
3. 将权重写入 `out/pretrain_512.pth`
4. 自动运行一条短文本推理并退出

本次整条 demo 命令实测约 11.6 秒，含 Python 启动和权重保存；运行时间会随系统负载变化。单独运行 `./run_eval.sh` 时，有终端会提示选择自动测试或手动输入；手动模式输入空行退出。也可显式传 `--input_mode 0`，或 `--prompt "你好"` 执行单条输入。

也可以拆开执行：

```bash
.venv/bin/python -m trainer.train_pretrain \
  --device cuda \
  --data_path dataset/demo_pretrain.jsonl \
  --save_dir out \
  --from_weight none \
  --from_resume 0 \
  --epochs 1 \
  --batch_size 2 \
  --max_seq_len 128 \
  --accumulation_steps 1 \
  --log_interval 1 \
  --save_interval 1

DEVICE=cuda ./run_eval.sh
```

训练输出同时会写入 `out/` 和 `checkpoints/`。代码现在会把相对路径统一解释为项目根目录，因此从根目录或 `trainer/` 目录执行都可以。

## 5. 换成真实数据

原教程的 ModelScope `pretrain_hq.jsonl` 链接在本次验证时返回 404。目前上游提供 `pretrain_t2t_mini.jsonl` / `sft_t2t_mini.jsonl`，本项目的 `scripts/prepare_data.py` 通过 Hugging Face 流式读取子集，分别提取 `text`、`conversations`，保留当前代码支持的角色和回答内容。上游新版本的独立 `reasoning_content` 不参与这个 SFT 实验，这也不是对旧数据版本的逐字复现。

先各下载 4096 条；达到数量后会关闭下载，不需要完整下载整个文件。本机已经取了 128/64 条真实样本进行限步验证；执行下列命令会将它们替换成更大的子集。

```bash
.venv/bin/python scripts/prepare_data.py --kind pretrain --max_samples 4096
.venv/bin/python scripts/prepare_data.py --kind sft --max_samples 4096

.venv/bin/python -m trainer.train_pretrain \
  --device cuda \
  --data_path dataset/pretrain_day.jsonl \
  --save_dir out/day \
  --checkpoint_dir checkpoints/day \
  --from_weight none \
  --from_resume 0 \
  --epochs 1 \
  --batch_size 2 \
  --max_seq_len 512 \
  --accumulation_steps 8 \
  --max_steps 200 --log_interval 10 --save_interval 40

.venv/bin/python -m trainer.train_full_sft \
  --device cuda \
  --data_path dataset/sft_day.jsonl \
  --save_dir out/day \
  --checkpoint_dir checkpoints/day \
  --from_weight pretrain \
  --epochs 1 --batch_size 2 --max_seq_len 512 \
  --max_steps 200 --log_interval 10 --save_interval 40

.venv/bin/python eval_llm.py --save_dir out/day --weight full_sft \
  --max_new_tokens 64 --prompt "为什么天空是蓝色的？"
```

`--max_steps` 是每个 epoch 的 batch 上限，`0` 表示不限；`--accumulation_steps 8` 表示每 8 个 batch 更新一次参数，最后不足 8 个的尾批也会更新并保存。短训只用于确认流程及估算耗时，200 步不保证有可用的聊天质量。

中断恢复时，保持数据、batch size、模型结构、`max_steps` 等参数不变，增加 `--from_resume 1`。恢复到本轮已完成的最后一个 batch 后，该轮会跳过；要再跑一轮，把 `--epochs 1` 改为 `--epochs 2`。检查点文件包含模型、优化器、scaler、epoch 和 batch 进度，不包含 DataLoader worker 的随机状态；本日主路径为固定 tokenizer、无 dropout 的单卡训练。

LoRA 使用另一输出目录，若要基于 `out/day/full_sft_512.pth`，额外传 `--weight_dir out/day`。`out/` 是 demo，`out/day/` 是真实数据实验，分别保存断点方便核对。

第一天先用 `--epochs 1`、`--max_seq_len 512` 和小 batch 验证吞吐及内存，再调整样本数和训练步数。当前只有一块 GPU，直接用普通 Python 启动。训练脚本的 `--use_wandb` 实际接入的是 SwanLab，可在本地训练稳定后单独启用。

## 7. 实测结果与排错

本机完成了 demo 闭环（约 11.6 秒）、18 项回归测试、真实数据 512 token 预训练（4 batch 约 4.3 秒，含进程启动和保存）、断点恢复进入下一轮、真实数据 SFT/LoRA，以及两种权重的重新加载推理。短训预训练的 loss 为 8.929 → 8.793；这些数字用于确认流程，不作为模型能力指标。

### 本次 demo 输出解读

本次运行的关键输出可以按下面的顺序理解：

- `device=cuda` 和 `cuda_available=True`：程序使用 GPU，PyTorch 能访问 CUDA。
- `torch=2.14.0+cu130`：PyTorch 版本为 2.14.0，使用 CUDA 13.0 运行库。
- `logits_shape=(1, 9, 6400)`：模型输出张量的形状是 `[B, T, V]`。`B=1` 表示一次处理一条样本，`T=9` 表示这条文本被切成 9 个 token，`V=6400` 表示词表有 6400 个候选 token。
- `logits` 是模型最后一层输出的原始分数，还不是概率。对位置 `t` 来说，`logits[0, t, :]` 给出 6400 个候选下一个 token 的分数；经过 softmax 才能得到概率，再用真实目标 `Y` 计算交叉熵 loss。训练中输入 `X` 和目标 `Y` 错开一位，所以位置 `t` 的输出用于预测下一个 token。
- `generated=...`：smoke test 用随机初始化的小模型做生成，只验证生成接口和张量形状，重复词或混乱文本是正常的。
- `loss=8.668865`：smoke test 的交叉熵损失，主要确认前向和数值计算有效，不能当作聊天能力分数。
- `backward and KV cache checks passed`：反向传播产生了有效梯度；带 KV cache 的增量前向与完整前向结果一致。
- `所加载Model可训练参数：25.830 百万`：预训练时会更新约 2583 万个参数。`MiniMind模型参数: 25.83 M(illion)` 是推理时加载的模型总参数量；全量预训练时两者相同。
- `Epoch:[1/1](1/3)`：总共训练 1 轮，当前是本轮第 1 个 batch，共 3 个 batch。`lr` 是学习率，本次按余弦调度从约 `5e-4` 降到 `5e-5`。`epoch_Time:0.0min` 是向下取整后的剩余时间估计。
- `👶` 后面是输入提示词，`🤖️` 后面是模型生成内容。demo 只有少量样本和几步更新，生成质量还不能代表完整训练效果。

下一步进入 [逐步调试教程](0.逐步调试.md) 的第 1 站，先只观察真实 batch 的输入、标签和 mask：

```bash
.venv/bin/python scripts/debug_train_step.py --stop_after data --token_rows 16
```

重点核对 `X`、`Y` 的错位关系，以及 `loss_mask` 哪些位置会计入损失；完成后再把 `--stop_after data` 改成 `forward`，观察 `logits` 如何从 `[1, 63]` 变成 `[1, 63, 6400]`。

- 找不到权重：先跑第 3 节，确认 `out/pretrain_512.pth` 存在。真实数据实验同时传 `--save_dir out/day`；LoRA 的基础权重目录使用 `--weight_dir`。
- 找不到数据：直接使用 `dataset/demo_*.jsonl`，或运行第 5 节限量下载命令。旧的 `pretrain_hq.jsonl` 下载链接已失效。
- 非交互环境出现 EOF：传 `--prompt` 或 `--input_mode 0`；当前推理脚本也会在无终端时默认自动测试。
- `Python.h` 缺失：本次直接依赖全部使用 wheel，普通训练已验证不需要源码编译。自行启用 Triton JIT 或编译其他扩展属于另一条环境路径，需要相应开发头文件。
- `uv pip check` 提示 `nvidia-cusparselt-cu13` 平台不符：本次下载的 0.8.1 ARM64 wheel 内部 `WHEEL` 标签为 `manylinux2014_sbsa`，但 wheel 文件名为 `aarch64`、库的 ELF 架构也是 AArch64；当前训练和推理均已通过。这是本次仍存在的包元数据检查提示，未通过修改包元数据来隐藏。

VLM、PPO、DPO、GRPO、蒸馏和多卡训练未做完整实测；它们需要额外数据、奖励模型、教师模型或 CLIP 权重。完成上面的预训练/SFT/LoRA/推理后，再按对应章节逐个启用。
