# 实践排错：先确认卡在哪一步

把一次练习拆成“启动 → 数据 → 前向 → 反向 → 更新 → 保存 → 重载”。报错时先确认最后成功的一步，再检查下一步的输入，不需要从头重装环境。

## 1. 程序还没启动

```bash
pwd
.venv/bin/python -c "import sys, torch; print(sys.executable); print(torch.__version__)"
```

当前目录应是项目根目录，解释器应来自项目 `.venv`。`python: command not found` 不表示项目环境缺失，课程命令使用 `.venv/bin/python`。

VS Code 选择仓库提供的调试配置。第 7 项会先停在入口，按 F5 继续，或者在对应 `lesson_...()` 函数设置断点。

## 2. 已启动，但 DATA 阶段不对

| 现象 | 先看什么 | 下一步 |
| --- | --- | --- |
| 找不到 demo 数据 | `data_path` 与目录 | 用仓库 `dataset/demo_*.jsonl`，先不下载大文件 |
| SFT 报 `no supervised tokens` | `max_seq_len`、截断后的文本 | 增加长度，确认回答没有全部被截掉 |
| 把 token ID 当成字串 | `X[0,0].item()` | 再用 tokenizer.decode 转成片段 |
| 有 63 个位置，却只有 19 个目标 | `loss_mask.sum()` | padding 保留张量位置，但不参与损失 |

先运行：

```bash
.venv/bin/python scripts/lesson_lab.py --lesson data
.venv/bin/python scripts/lesson_lab.py --lesson sft
```

## 3. FORWARD 阶段看不到变量

DATA 停点还没有创建模型，不能在那里查看 logits。按 F5 到 FORWARD，再看：

```python
X.shape
logits.shape
loss.item()
```

教学脚本的形状通常是 `[1,63] → [1,63,6400]`，SFT 长度 128 时为 `[1,127] → [1,127,6400]`。原始训练循环里输出叫 `res.logits`，不是所有脚本都用同一个局部变量名。

调试箭头指向的语句尚未执行；在 `res = model(X)` 上停住时，这次 res 还没生成。

## 4. BACKWARD 后为什么参数没有变

这是正常分工：

```text
backward：产生或累加 .grad
step：使用梯度更新参数
zero_grad：清掉用过的梯度
```

三批、每两批累积的课程中，第一批结束不执行 step。不要为了让它“立刻变化”把每批的 zero_grad 移到循环开头，否则会丢掉前一批的梯度。

LoRA 第一轮 A 梯度为零也可能符合预期，因为 B 零初始化；看 B 是否有梯度，以及基础 W 是否保持冻结。

## 5. 保存与恢复卡住

先区分两个文件：

```text
out/debug_accum/pretrain_128.pth：模型状态，供加载使用
checkpoints/debug_accum/pretrain_128_resume.pth：模型、AdamW、进度等
```

如果只运行 `lesson_lab.py --lesson pretrain`，文件在临时目录，结束会清理。要让后续 SFT 使用持久化文件，先运行 VS Code 第 5 项配置。

恢复前保持数据、结构、batch、总步数等设置一致。checkpoint 的 batch step=3 与 AdamW 更新 step=2 是两个计数，不是冲突。用下面的受控实验对照：

```bash
.venv/bin/python scripts/lesson_lab.py --lesson resume
```

## 6. SFT / LoRA 重载推理失败

| 现象 | 检查方法 |
| --- | --- |
| 找不到 `full_sft_128.pth` | 确认已执行真实 SFT 入口，且 `--save_dir` 指向基础权重目录 |
| 矩阵 `size mismatch` | 加载时 hidden_size、层数、MoE 配置应与保存时一致 |
| 独立目录的 LoRA 找不到 | 用 `--lora_path` 指向附件文件，不把它作为基础模型目录 |
| token 变得不认识 | 检查是否换过 tokenizer；同样大小的词表不保证 ID 语义一致 |

128 维、两层的课程模型需要在推理时也传 `--hidden_size 128 --num_hidden_layers 2`。省略时会使用其他默认结构。

独立 LoRA 附件的完整命令见 [LoRA](6.LoRA.md)。不带附件的基础重载命令见 [SFT](5.SFT.md)。

## 7. 输出混乱、loss 波动或时间异常

少量 demo 只验证流程。loss 每批变化还与题目不同有关；日志不是固定输入的前后测试，也不是准确率。要测更新效果，控制输入和随机性，重新前向对照。

`epoch_Time` 包含调试暂停，而且原估算公式有取整与计数偏差；不能拿它比较训练速度。

CUDA 不可用时先使用 CPU 小实验，不要把完整训练的 batch size 直接照搬到小设备上。外部奖励模型、教师权重和 CLIP 属于额外前置依赖，本地数学算例通过不会替你安装它们。

## 8. 改完文档，先检查入口与代码块

```bash
.venv/bin/python scripts/check_course.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/lesson_lab.py --lesson all
```

三条分别检查课程静态内容、代码回归与教学计算。静态检查不执行 Markdown 中的命令，也不检查外部网址可达性。没有报错之后，再用本章的具体完成标准检验自己是否理解了变量与状态变化。
