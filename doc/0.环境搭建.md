# 环境搭建

历史验证环境为 Linux ARM64、NVIDIA GB10、Python 3.12.3，驱动支持 CUDA 13.0。本仓库在该环境验证了 PyTorch `2.14.0+cu130`、torchvision `0.29.0` 和 Transformers `4.57.1`。它们是课程的已验证组合，不表示需要升级现有环境。

完整的当天操作顺序、数据准备、训练、恢复和推理见 [一天跑通教程](0.一天跑通.md)。

## 先认识三层环境

```text
系统 NVIDIA 驱动：让操作系统和 GPU 通信
项目 .venv：隔离 Python 与依赖版本
PyTorch CUDA 运行库：让张量算子在 GPU 上运行
```

驱动可用不等于当前 Python 已安装 torch；系统有其他 Python 也不等于 VS Code 选中了项目 `.venv`。先看 `sys.executable`、torch 版本和 CUDA 是否可用，再排查训练代码。

可以把三层想成“公路、工作间、运输工具”：驱动提供系统访问 GPU 的能力，虚拟环境决定本次 Python 能导入哪些包，PyTorch 才负责把张量放到设备上计算。

| 观察值 | 能说明什么 | 还不能说明什么 |
| --- | --- | --- |
| `sys.executable` | 实际启动了哪个 Python | 依赖一定兼容 |
| `torch.__version__` | 当前 Python 导入的 torch 版本 | GPU 一定可访问 |
| `torch.version.cuda` | 此 torch 构建对应的 CUDA 运行库 | 当前设备或驱动可用 |
| `torch.cuda.is_available()` | 此进程能否使用 CUDA | 数据、模型、保存流程均正确 |

已配置的当前工作区直接进入下方检查，不需要反复重建虚拟环境：

```bash
.venv/bin/python -c "import sys, torch; print(sys.executable); print(torch.__version__); print(torch.cuda.is_available())"
.venv/bin/python scripts/lesson_lab.py --lesson tokenizer
```

前一条验证解释器与设备，后一条验证本地词表和依赖。无 CUDA 也可完成 CPU 教学小实验；GPU 主要用于后续更大的训练。全课程路线见 [学习路线](0.学习路线.md)。

## 使用已有 uv 和 Python

在仓库根目录执行：

```bash
uv venv .venv --python /usr/bin/python3
UV_CACHE_DIR="$PWD/.uv-cache" uv pip install \
  --python .venv/bin/python --index-url https://pypi.org/simple \
  -r requirements-aarch64.lock

.venv/bin/python scripts/smoke_test.py
.venv/bin/python -m unittest discover -s tests -v
bash trainer/run.sh
```

当前工作区已经配置好 `.venv`，可以直接运行 smoke test。系统驱动无需修改，项目所需 CUDA 运行库随 PyTorch wheel 安装。`.txt` 为直接依赖清单，`.lock` 为本机解析并验证的完整依赖锁定。

### 为什么命令总写 `.venv/bin/python`

终端、VS Code、Notebook 可能选中了不同解释器。直接使用项目解释器路径，让安装依赖与运行训练使用同一套 Python。

如果 `pip install` 装到了系统环境，而调试器使用 `.venv`，就会出现“刚安装仍找不到包”。先比较路径，比重装环境更容易定位问题。

下面的独立检查不安装或修改依赖：

```python
# doc-example: environment
import platform
import sys
import torch
from importlib.metadata import version

print("Python:", sys.executable, platform.python_version(), platform.machine())
print("torch / transformers:", torch.__version__, version("transformers"))
print("CUDA build / usable:", torch.version.cuda, torch.cuda.is_available())
x = torch.arange(6, dtype=torch.float32).reshape(2, 3)
y = x @ x.T
torch.testing.assert_close(y, torch.tensor([[5., 14.], [14., 50.]]))
if torch.cuda.is_available():
    torch.testing.assert_close((x.cuda() @ x.cuda().T).cpu(), y)
print("解释器与矩阵运算检查通过")
```

先在 CPU 验证乘法，再在可用时搬到 CUDA。`.to("cuda")` 改变保存与计算设备，没有把输入换成另一份训练数据。

## 可选 Pixi

`pixi.toml` 已支持 `linux-aarch64` 和 `linux-64`。`pixi.lock` 由 Pixi 0.84.2 重新生成，使用新的 v7 锁文件格式：

```bash
pixi install --locked
pixi run check-gpu
pixi run smoke
pixi run test
pixi run demo
```

本机下载的 Pixi 可通过 `.tools/pixi` 调用；实际训练验证使用 uv 环境，Pixi 路线已完成依赖解析和锁文件更新。选用其中一条路线即可。

## 在 VS Code 中固定同一实验条件

以仓库根目录作为工作区，选用已有的 `.vscode/launch.json`，它们显式指定解释器、工作目录和入口。打开父目录后，`${workspaceFolder}` 就不再自动代表项目根目录。

| 现象 | 先核对 | 理由 |
| --- | --- | --- |
| 终端能跑，F5 不能跑 | 解释器与 cwd | 两个入口可能不在同一环境 |
| `ModuleNotFoundError` | Python、模块搜索路径 | 不一定是包没安装 |
| CUDA 不可用但 CPU 正常 | torch 构建、驱动可见性 | 先不改模型公式 |
| wheel 不匹配 | 平台与锁文件路线 | ARM64 与 x86_64 不能混用 |

完成标准：能指出用哪个 Python、导入哪个 torch、张量在哪个设备，并运行一个小矩阵乘法。然后进入 [一天跑通](0.一天跑通.md) 或 [逐步调试](0.逐步调试.md)。
