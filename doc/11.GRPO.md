# 11. GRPO：同一个问题，比较几份回答

GRPO 是 **Group Relative Policy Optimization，组相对策略优化**。前置：[SFT](5.SFT.md)、[PPO 的奖励与优势](7.PPO.md)。本章对照 [train_grpo.py](../trainer/train_grpo.py)，先做组内比较的小实验，再考虑奖励模型与完整训练。

## 1. 用同题多答代替一个独立的评分预测员

```text
同一个问题
  ├─ 回答 A -> 奖励 1
  ├─ 回答 B -> 奖励 2
  └─ 回答 C -> 奖励 3
组内均值为 2
```

相对于本组，A 低于平均、B 等于平均、C 高于平均。GRPO 用这种组内反馈构造优势，不需要像 PPO 一样训练 Critic 来提供价值基线。

不需要 Critic 不等于“不需要评分”：当前脚本仍需要奖励模型，并可加入格式奖励。输出 `<think>` 等标签也不证明推理内容正确。

## 2. 手算一组优势，再对照代码

假设奖励 `[1,2,3]`，按当前 PyTorch 默认样本标准差计算，std=1：

```text
均值：2
优势：(reward-2)/(1+1e-4)
约为：[-0.9999,0,+0.9999]
```

本脚本后面还做 clamp 与整个 batch 的再次标准化，所以训练中最后看到的数值可能改变。上面的数对应第一阶段组内计算。

G=1 时默认样本标准差无法正常估计；加 epsilon 不会把 NaN 变好。学习实验用 G=3，完整训练应保证分组数量和排序正确。

同组奖励都相同时，相对反馈为 0；这不意味着回答全对或全错，只说明这一组评分没有区分它们。

## 3. 为什么 ratio 明明是 1，仍然有梯度

当前脚本有：

```python
ratio = torch.exp(logp - logp.detach())
```

假设 `logp=-0.5`：

```text
数值：exp(-0.5-(-0.5)) = 1
求导：detach 后的第二项视为常量
所以对前一个 logp 的导数仍为 exp(0) = 1
```

这是一种保留策略梯度的构造。不能把两项当成同一个可求导变量直接抵消，也不能说它是一个记录了历史采样策略的 old_logp。

当前入口没有保存旧策略概率再进行 PPO 式 ratio clipping，不能与第 13 章的 clipped GRPO 教学类视为同一个实现。该入口更接近单次采样更新的策略梯度加组内基线与 KL 相关项。

## 4. 回答级优势怎样用到每个 token

```text
B 个问题，每题 G 个回答
生成 outputs：[B*G,P+R]
回答部分：    [B*G,R]
逐 token logp：[B*G,R]
回答优势：    [B*G] -> unsqueeze -> [B*G,1]
```

同一个回答的各个有效 token 共享该回答优势，不表示每个 token 对得分有完全相同的因果贡献。completion_mask 用于截止 EOS，排除后面的填充。

当前代码先对每个回答的有效 token 求均值，再对回答求均值；不是统一把所有回答的所有 token 加起来除以总长度。不同回答长度不同时，两者权重不同。

## 5. KL 相关项与奖励要分开观察

令 `d=ref_logp-logp`，当前每 token 使用：

```python
per_token_kl = torch.exp(d) - d - 1
```

由 `exp(d) >= 1+d`，这个数非负，d=0 时为 0。但某个采样位置为零只表示该位置所选 token 的 log probability 相同，不能据此证明两份完整词表分布一致。把它称为 KL 估计还需要对应的采样条件。

格式分、内容奖励、优势、KL 正则分别承担不同角色。只盯着平均奖励升高，不检查回答内容和评分规则，容易把格式模仿当成能力提升。

## 6. 本地实验与可改的旋钮

```bash
.venv/bin/python scripts/lesson_lab.py --lesson grpo
```

预期组内优势约 `[-1,0,1]`；ratio 的值是 `[1,1]`，对 logp 的梯度也是 `[1,1]`。这是关键表达式算例，不加载奖励模型。

动手先把奖励整体加 10，再比较组内优势；然后把奖励全部改为 2，观察优势为 0。最后只提高某一个回答的奖励，解释组内其他回答的相对位置为什么也改变。

VS Code 用第 7 项配置选择 `grpo`，在 `ratio.sum().backward()` 前后分别看 ratio 的值和 logp.grad。

完整训练还需要相同基础权重、奖励模型、prompt 数据、采样长度与有效 mask 的核对。本机没有用这个小算例代替端到端 GRPO 验证。

完成标准：解释为何无 Critic 仍需 reward、为何按同题分组，以及“ratio 值为 1”与“梯度为零”的区别。进一步推导见 [数学附录](13.强化学习刨根问底.md)。
