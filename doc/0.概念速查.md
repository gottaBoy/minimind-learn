# 概念速查：把名字放回同一台接龙机器

配合 [学习路线](0.学习路线.md) 使用。比喻用于建立直觉，张量形状和真实代码用于核对边界。

## 1. 先分清零件、数值和操作

| 名词 | 直观含义 | 实际代码中是什么 | 容易混淆的地方 |
| --- | --- | --- | --- |
| token | 文本的一片零件 | 词表中的条目 | 不一定是一个字或一个完整单词 |
| token ID | 零件编号 | 整数，如 `M → 47` | ID 大小不是重要性或概率 |
| tokenizer | 拆零件并查编号的规则 | 编码、解码与词表 | 换了编号表不能直接沿用旧权重 |
| Embedding | 根据编号查向量卡片 | 可训练的 `[V,H]` 表 | 向量不是人为写好的语义说明 |
| hidden state | 当前上下文的内部表示 | `[B,T,H]` 浮点张量 | H 不是词表大小 |
| logits | 每个候选的原始分数 | `[B,T,V]` | 还不是概率，也不是最终 token |
| probability | softmax 后的候选概率 | 每个位置总和为 1 | 高概率不保证事实正确 |
| label / Y | 这道接龙题的标准答案 | 错后一位的 token ID | 不来自模型当前的猜测 |
| loss | 当前预测相对目标的损失 | 通常汇总为标量 | 不是梯度，也不是准确率 |
| parameter | 机器内部可调整的数值 | `nn.Parameter` | 与命令行超参数不同 |
| gradient | 损失对参数的变化率 | `parameter.grad` | 写下梯度不等于修改参数 |
| optimizer | 执行调整的规则与历史状态 | 如 AdamW | 不负责分词或生成目标答案 |
| learning rate | 调整过程的尺度设置 | 参数组中的 `lr` | AdamW 更新量不简单等于 lr×当前梯度 |
| reward | 外部评价回答的分数 | 标量或逐位置奖励 | 可以为负，不是 0～1 概率 |
| value | 对未来回报的估计 | Critic 的输出 | 与真实获得的 reward 不同 |
| advantage | 比基线好或差多少 | PPO/GRPO 的学习信号 | 不等于原始奖励本身 |

例子：题目是 `M → in`，`47` 是输入编号，`261` 是正确答案编号。模型输出 6400 个 logits；交叉熵检查目标 261 得到的概率，再由 backward 求出参数梯度。

### 同一位置的几个数字不能互换

```text
输入 ID = 47              查表用的整数
目标 ID = 261             希望接出的片段
目标 logit ≈ 0.382358     6400 项分数中的一项
目标概率 ≈ 0.00019090     与所有候选比较后的归一化结果
本题 loss ≈ 8.563768      -log(目标概率)
```

这是当前真实小模型第一个位置的例子。261 不是“261 分”，0.382358 也不是“38% 的正确率”。单个 logit 必须与同一位置其他候选共同判断。

## 2. 常见形状怎么读

| 记号 | 本课值 | 对应问题 |
| --- | --- | --- |
| B | 1 | 一次有几条样本？ |
| T | 63 | 每条有几个预测位置？ |
| H | 128 | 每个位置的内部向量有多宽？ |
| V | 6400 | 每个位置有多少候选 token？ |
| G | 例如 3 | GRPO 中同一问题生成几份回答？ |
| K | 例如 2 | MoE 中每个 token 选几个路由专家？ |

```text
X/Y/mask：[B,T]        每个位置一个编号或标记
hidden： [B,T,H]       每个位置一个 H 维表示
logits： [B,T,V]       每个位置一张 V 项候选打分表
```

有的公式用 T 表示蒸馏温度，有的用 T 表示序列长度。阅读时先看该节定义，不要只凭字母猜含义。

### 行、列、轴和元素个数

`[1,63,128]` 有三个轴、8064 个数。`x[0,0]` 选一个位置的 128 维向量，`x[0,0,7]` 才选中一个数。

| 操作 | 本课形状 | 做了什么 |
| --- | --- | --- |
| reshape | `[1,63,128] → [63,128]` | 重新组织维度，元素数不变 |
| transpose | `[1,63,8,16] → [1,8,63,16]` | 交换两个轴 |
| `@` | `(63×128) @ (128×32)` | 沿 128 项求和，得到 `63×32` |
| `*` | 两份 `[1,63,384]` | 对应元素相乘 |
| sum | `[1,63] → 标量` | 将指定范围的数相加 |

行列式是方阵可以计算的一个标量，不等于 `m×n` 形状。先标清每条轴代表谁，再讨论矩阵计算。

## 3. 三种 mask 分别控制什么

| mask | 控制的问题 | 例子 |
| --- | --- | --- |
| 因果 attention mask | 当前预测能否读取后文？ | 位置 0 不能偷看位置 1 |
| padding attention mask | 某个输入位置是否可作为注意力的 key？ | 忽略用于组批的补齐位置 |
| loss mask | 某个目标位置是否计入损失？ | SFT 的用户问题为 0，回答为 1 |

loss mask 必须与 Y 对齐。mask 为 0 不等于删除输入，也不等于模型完全看不到那段内容。预训练入口 `model(X)` 没有显式传入 padding attention mask；当前因果模型右侧补齐下，有效正文的预测不会读取后面的 padding。

## 4. 三种 softmax 也别混在一起

| 场景 | 对哪些候选归一化 | 得到什么 |
| --- | --- | --- |
| 最后的词表预测 | V 个 token | 下一个 token 的概率 |
| Attention | 当前可见的上下文位置 | 汇总 V 向量时的权重 |
| MoE gate | E 个路由专家 | 专家选择的分数与融合权重 |

Attention 里的 V 指 Value 向量；形状记号里的 V 常指词表大小，二者恰好同名，含义不同。

SiLU 不是 softmax，也不把数值限制在 0～1；例如 `SiLU(-1)≈-0.269`、`SiLU(2)≈1.762`。

## 5. batch、epoch 和 step

把六条数据看成六张练习纸，`batch_size=2` 表示每次拿两张，完整一轮有三批。`accumulation_steps=2` 表示通常每两批汇总一次梯度。

```text
处理的批数： 1  2  3
是否更新：   否 是 是（最后一批补做尾组更新）
```

本仓库预训练日志和 checkpoint 的 `step` 记录已处理 batch 数；AdamW 参数状态里的 `step` 记录更新次数。其他项目可能采用不同约定，需要对照实际代码。

### AMP、DDP、梯度累积不是一件事

| 名称 | 全称 | 当前解决的问题 |
| --- | --- | --- |
| AMP | Automatic Mixed Precision | 选择合适的计算精度，降低显存和计算成本 |
| DDP | DistributedDataParallel | 多进程、多 GPU 分片数据并同步梯度 |
| 梯度累积 | Gradient Accumulation | 多个 batch 的梯度合并后再更新参数 |
| Checkpoint | 训练状态快照 | 保存参数、优化器历史和进度，便于恢复 |

本课实际三批配置为 `accumulation_steps=2`：

```text
batch 1：backward，不 step
batch 2：backward + step，第 1 次更新
batch 3：尾组 backward + step，第 2 次更新
```

AMP 不会自动让模型更新更频繁；DDP 也不等于梯度累积。三者可以一起使用，但分别作用于精度、设备并行和更新频率。

AMP 的当前精度条件：

```text
CPU/float32       -> 无 autocast、无 GradScaler
CUDA/bfloat16     -> autocast，通常不启用 GradScaler
CUDA/float16      -> autocast + GradScaler
```

## 6. 四个动作，只有一步修改参数

```text
forward      算预测与 loss
backward     沿计算图累加梯度
step         使用梯度和优化器状态修改参数
zero_grad    清除已用梯度，保留参数更新
```

`eval()` 切换某些模块的行为，例如 Dropout；`no_grad()` 控制是否记录自动求导图。冻结参数用 `requires_grad_(False)`。这三件事互不等价。

### 为什么恢复时要跳过数据

checkpoint 的 `step` 在本仓库表示**已处理的 batch 数**。如果保存时 `step=2`，恢复时要先恢复同一轮 sampler 顺序，再由 `SkipBatchSampler(skip_batches=2)` 丢弃前两批。

```text
只改显示编号：      batch 1、batch 2、batch 3 仍会被读取
恢复顺序 + 跳过批次：只读取尚未处理的 batch 3
```

这样避免重复训练已包含在当前参数里的数据，也让学习率调度和数据进度保持对应。当前实现不保存完整随机状态，所以这种一致性限定在固定数据、sampler、设备和 dropout 条件下。

### 独立实验：分数、概率、损失和梯度

为方便手算只保留三个候选；真实模型对 6400 个候选执行同类规则。

```python
# doc-example: score-probability-loss
import torch
import torch.nn.functional as F

scores = torch.tensor([[2., 1., 0.]], requires_grad=True)
target = torch.tensor([1])
probability = scores.softmax(-1)
loss = F.cross_entropy(scores, target)
torch.testing.assert_close(loss, -probability[0, 1].log())
loss.backward()
expected_gradient = probability.detach().clone()
expected_gradient[0, 1] -= 1
torch.testing.assert_close(scores.grad, expected_gradient)
print("概率：", probability.detach().tolist())
print("loss：", loss.item(), "分数梯度：", scores.grad.tolist())
```

正确项是第 1 项，不是当前分数最高的第 0 项。梯度下降倾向提高正确项分数、降低其他项；这里检查对 logits 的导数，真实参数还要经过更长的计算图。backward 后 scores 的值没有自动更新。

## 7. 各训练方法到底换了哪里

| 方法 | 主要变化 |
| --- | --- |
| Pretrain | 从连续正文得到下一个 token 监督 |
| SFT | 加入角色模板，选择回答相关目标监督 |
| LoRA | 冻结基础矩阵，训练低秩增量分支 |
| DPO | 用 chosen/rejected 相对参考模型的偏好差计算损失 |
| 蒸馏 | 学习教师的软概率或生成的训练回答 |
| PPO | 生成、评奖、估计优势，更新 Actor 和 Critic |
| GRPO | 同题多答，以组内奖励形成相对优势 |
| MoE | 替换部分 FFN 结构，路由到若干专家 |
| VLM | 将投影后的图像特征放进语言序列 |

这些不是一个互斥的清单。例如可以对 MoE 模型做 SFT，也可以用 LoRA 执行 SFT。先分清“数据任务、损失、参数更新范围、模型结构”四个位置，后续章节就能接在同一条线上。

## 8. 读日志时再区分三类量

| 类别 | 例子 | 什么时候确定 |
| --- | --- | --- |
| 超参数 | H=128、batch=1、学习率 | 实验前配置，或由调度规则产生 |
| 模型参数 | E、Wq、W_gate | 初始化或加载，优化器更新 |
| 当前结果 | logits、loss、grad norm | 随当前输入和参数计算产生 |

`loss=8.9` 不是模型保存的“知识参数”；H=128 也不是训练自己选出的长度。读变量时，先说它是配置、参数、输入、激活、目标、梯度还是优化器状态，再说 shape 和生命周期。
