# 7. PPO：让生成的回答接受奖励反馈

前置：[SFT](5.SFT.md)、[概率与梯度](0.概念速查.md)。本章对照 [train_ppo.py](../trainer/train_ppo.py)，完整奖励模型和多卡训练尚未在本机实测；可以先运行无需额外模型的 GAE 与损失实验。

## 本章实践卡

先不加载奖励模型，跑三个局部计算：

```bash
.venv/bin/python scripts/lesson_lab.py --lesson ppo
```

对照输出时只问三个问题：终点奖励如何倒推到前面？正优势和负优势的 clip 方向有什么不同？`value`、`return`、`advantage` 分别表示什么？

完整 `train_ppo.py` 需要外部 Reward Model、RLAIF 数据和更大显存。本章的小实验证明公式和本仓库 `GAE` 函数能对上，不等于端到端 PPO 已经运行。

## 1. 从“有答案的练习”变成“先作答，再评价”

SFT 直接给标准回答。PPO 先让 Actor 生成回答，再用外部规则或奖励模型评价，形成调整策略的信号：

```text
问题 -> Actor 生成 -> Reward 给分
                       ↓
Critic 估计价值 -> GAE 把反馈关联到各位置
                       ↓
新旧策略概率比 + 裁剪目标 -> 更新
```

奖励不是事实正确性的自动保证，格式奖励高也不等于推理正确。要先定义评分规则，再解释模型究竟在优化什么。

### 一条回答如何变成一次训练材料

以生成三个 token 为例，先固定本次采样得到的三个 ID，再重新计算这些动作在当前策略下的概率。奖励模型对整段回答给分；这个分数不是每步词表的标准答案。

```text
采样时：问题 -> a0 -> a1 -> a2 -> 结束 -> reward
更新时：同一条轨迹 -> 各动作 logp -> 优势 -> 策略损失
```

不能在比较新旧概率时换成另一份新回答，否则分子分母比较的不是同一动作和状态。token 的离散采样本身不直接按普通链式法则求导；更新依靠所选动作的 log probability 构造信号。

## 2. 不同模型是不同角色

| 对象 | 形象理解 | 本脚本职责 |
| --- | --- | --- |
| Actor | 作答者 | 生成回答、计算当前 token 对数概率 |
| Old Actor | 一份滞后的作答策略快照 | 给 PPO 比率提供旧概率 |
| Reference | 固定参照版本 | 估计与参考分布的偏移 |
| Critic | 预计接下来能拿几分 | 输出每个位置的价值估计 |
| Reward Model | 外部评分员 | 对生成文本给分 |

Old Actor 与 Reference 不能混为一谈：前者对应策略更新的比较基准，后者是长期参考。源码的 `CriticModel` 新增 `value_head`，其 forward 返回 `[B,T]` 价值张量，不是词表 logits。

### Actor 的 6400 个数与 Critic 的 1 个数

Actor 的头从 `[B,T,128]` 得到 `[B,T,6400]`，回答“下一片是谁”；Critic 的 value_head 从隐藏表示得到 `[B,T,1]`，再 squeeze 为 `[B,T]`，回答“这个状态预计还能得到多少回报”。

预计得分不是下一个 token 的概率，也不必在 0～1。Reward Model 评价已经生成的内容；Critic 则学习预测回报，两者不是同一个评分来源。

## 3. 最后一刻的奖励，怎样影响前面的动作

设三步回答结束时才得到奖励 1：

```text
位置：        0    1    2
即时奖励：    0    0    1
Critic 估计：0.2  0.3  0.4
是否结束：    否   否   是
```

用教学设置 `gamma=1`、`lambda=1` 手算，终点之后的 value 为 0：

```text
delta2 = 1 + 0   - 0.4 = 0.6
delta1 = 0 + 0.4 - 0.3 = 0.1
delta0 = 0 + 0.3 - 0.2 = 0.1

A2 = 0.6
A1 = 0.1 + A2 = 0.7
A0 = 0.1 + A1 = 0.8
```

不是把 reward 1 原样复制给所有位置，而是结合价值估计和终止条件倒推反馈。一般形式为：

$$
\delta_t=r_t+\gamma(1-d_t)V_{t+1}-V_t,\qquad
A_t=\delta_t+\gamma\lambda(1-d_t)A_{t+1}.
$$

当前训练入口调用了真实 `GAE` 类，使用 `gamma=0.99`、`lambda=0.95`，并为有效回答位置建立 mask；不能用旧说明中的单个 `rewards-values` 代替整段实现。实验将系数设为 1，仅为了方便手算。

### 调用真实 GAE，改变反馈传播范围

```python
# doc-example: gae-terminal-reward
import numpy as np
from trainer.train_ppo import GAE

reward = np.array([[0., 0., 1.]], dtype=np.float32)
value = np.array([[0.2, 0.3, 0.4]], dtype=np.float32)
done = np.array([[0., 0., 1.]], dtype=np.float32)
full = GAE(1, 3, gamma=1., lambda_=1.)(done, reward, value)
local = GAE(1, 3, gamma=1., lambda_=0.)(done, reward, value)
np.testing.assert_allclose(full, [[0.8, 0.7, 0.6]], atol=1e-6)
np.testing.assert_allclose(local, [[0.1, 0.1, 0.6]], atol=1e-6)
np.testing.assert_allclose(full + value, [[1., 1., 1.]], atol=1e-6)
print("完整倒推：", full, "只保留当前 TD 残差：", local)
```

lambda=0 时不继续累加下一步优势，所以最前面的反馈较小。done 切断轨迹之后的反馈，不是把当前这一步奖励删除。

真实变长回答还需排除 padding。`valid_mask` 决定哪些位置进 loss，`done_dense` 决定递推在哪里终止，二者不能互相替代。

## 4. 策略比率和裁剪，先手算一个数

```text
同一个已生成 token：
采样策略概率 0.2
当前策略概率 0.3
ratio = 0.3 / 0.2 = 1.5
```

若优势 A=1、epsilon=0.2：

```text
原目标       ratio * A = 1.5
裁剪分支     1.2 * A   = 1.2
选较保守值   min(...)  = 1.2
最小化 loss            = -1.2
```

在这条正优势分支已经超出上界时，继续提高 ratio 不再从该目标获得额外收益。裁剪作用于代理目标；它不是直接把模型参数或真实策略比率限制在区间内，也不保证训练稳定。

当前总损失是：

```python
loss = policy_loss + args.vf_coef * value_loss + args.kl_coef * kl_loss
```

最小化视角下 value loss 前是正号。Critic 学习目标为 `returns = advantages + values_dense`；policy、value 和 KL 各自的 mask 与对齐必须核对。

### 负优势要反过来理解

优势 A<0 表示这次动作相对基线更差。若 ratio 已经很小，进一步降低该动作概率不再从裁剪目标得到额外收益；如果 ratio 很大，目标仍会惩罚这次增幅。

```python
# doc-example: ppo-four-cases
import torch

ratio = torch.tensor([1.5, 0.5, 1.5, 0.5], requires_grad=True)
advantage = torch.tensor([1., 1., -1., -1.])
plain = ratio * advantage
limited = ratio.clamp(0.8, 1.2) * advantage
loss_map = -torch.minimum(plain, limited)
torch.testing.assert_close(loss_map, torch.tensor([-1.2, -0.5, 1.5, 0.8]))
loss_map.sum().backward()
torch.testing.assert_close(ratio.grad, torch.tensor([0., -1., 1., 0.]))
print("四种分支 loss / gradient：", loss_map.detach(), ratio.grad)
```

clip 是对代理目标某些方向停止额外激励，不是把所有梯度设零；优势正负决定哪个方向被截断。

## 5. 当前脚本与论文语义要分开

标准 PPO 的分母应对应生成这批样本时的行为策略。它可以来自当时保存的 log probability，也可以来自参数一致的旧策略快照。

当前脚本用 Actor 采样、用按频率更新的 Old Actor 计算分母；两者不一定始终一致。不能说这是比匹配采样策略更标准的做法，也不能认为 clipping 会自动修复这个差异。阅读时分别追踪生成时参数、分母来源和同步时机。

源码使用 `actor_logp-ref_logp` 的采样平均作为 KL 相关项。单个对数概率差可以为负；只有在指定分布下求期望，并满足相应采样条件时才对应 KL。采样还受温度、padding 和有效长度处理影响，所以不能无条件称当前数值或梯度为精确 KL。

完整训练还需要核对变长回答、末尾不足 batch、恢复时 `loader.batch_size` 的含义以及奖励模型接口。这些边界不由一个小算例通过来保证。

## 6. 无需奖励模型，先做本地实验

```bash
.venv/bin/python scripts/lesson_lab.py --lesson ppo
```

预期：

```text
advantages ≈ [[0.8,0.7,0.6]]
returns ≈ [[1,1,1]]
正优势裁剪目标为 1.2，该侧梯度为 0
PASS ppo
```

GAE 部分调用仓库真实类；裁剪部分单独验证损失表达式。它不运行 `generate()`，不加载 Reward Model，也不代表完整 PPO 已跑通。

动手改数：把终点奖励从 1 改成 0，先预测同样 value 下优势会变为负，再手算递推。把 A 改成负值时，也要重新计算 `min`，不能把正优势的截断方向照搬过去。

## 7. 读源码的停靠顺序

先看 `calculate_rewards` 的评分规则，再看 `ppo_train_epoch` 中 `rewards_dense / values_dense / done_dense / valid_mask` 的构造；之后进入 GAE，最后读 `get_batch_logprobs` 和损失。

`logits[t]` 预测的是 `input_ids[t+1]`，所以抽取回答 token 的概率时需要移位。`gather` 从 log_softmax 后的结果取数，得到的是 log probability，不是直接取原始 logit。

完成标准：用上面的三步例子解释 reward、value、advantage、return 的区别，并指出当前代码的采样分母假设。之后可读 [GRPO](11.GRPO.md) 对比没有 Critic 的方案，或读 [数学附录](13.强化学习刨根问底.md)。

### 一次调试必须对齐的三条坐标

| 对象 | 对齐到哪里 | 为何容易差一位 |
| --- | --- | --- |
| 动作 ID | 回答 token 所在位置 | 生成输出还含 prompt |
| 动作 logp | 前一个位置的 logits | logits[t] 预测 ID[t+1] |
| value | 明确定义的状态 | 动作前状态与动作后状态不同 |

源码的 `get_batch_logprobs` 从 `prompt_length-1` 开始取动作概率，而 Critic 切片使用回答位置。做完整算法核对时必须说明价值对应动作前还是动作后状态；维度吻合不能自动证明语义已对齐。

读完整入口的顺序：冻结本批轨迹 → 追踪分母快照 → 查看奖励落点和有效长度 → 核对 GAE → 查看 Actor/Critic 各自梯度 → 检查更新与保存。外部模型尚未准备时，先完成本章两段数值实验。

## 8. 从五个 prompt 位置对齐三个回答动作

```text
完整 input_ids 位置： 0 1 2 3 4 | 5 6 7
                       prompt | 回答 ID
预测回答所用 logits：         4   5   6
```

第一个回答 ID 在位置 5，由位置 4 的 logits 预测。截取 logits 从 5 开始，就错过了第一个动作，之后每项也错位。

下面使用本地文本与当前 128 维小模型验证真实 `get_batch_logprobs`，不生成文本或调用奖励模型：

```python
# doc-example: ppo-response-alignment
from transformers import AutoTokenizer
from scripts.lesson_lab import small_model
from trainer.train_ppo import get_batch_logprobs

torch.manual_seed(42)
tok = AutoTokenizer.from_pretrained("model")
tokens = tok("MiniMind is a small language model", return_tensors="pt").input_ids[:, :8]
assert tuple(tokens.shape) == (1, 8)
actor = small_model().eval()
attention_mask = torch.ones_like(tokens)
with torch.no_grad():
    aligned = get_batch_logprobs(actor, tokens, attention_mask, [5], 3)
    full_logits = actor(tokens).logits
    selected = full_logits[:, :-1].log_softmax(-1).gather(
        -1, tokens[:, 1:, None],
    ).squeeze(-1)
torch.testing.assert_close(aligned, selected[:, 4:7])
assert tuple(aligned.shape) == (1, 3)
print("三个回答动作的 log probability：", aligned)
```

这个实验没有 padding，便于先确认移位。扩展到变长、左侧 padding 和 EOS 时，要重新检查实际 prompt 长度、有效动作长度与 mask；不能只把 `[1,3]` 改成另一个 shape 就算完成。

### 价值目标不应继续反向流回优势估计

当前代码将 GAE 结果作为本次更新的固定反馈，Critic 用 `returns.detach()` 作为目标，Actor 使用计算好的优势。若让目标同时随当前预测参与求导，就改变了损失的含义。

可以把 Critic 训练想成“拿着这次计算好的回报估计改预测”，而不是一边改预测、一边让评分目标跟着移动，从而抵消误差。

### 结束与截断不是同一个概念

真正终止后不再有后续回报，可令下一状态 value 为 0。若仅因最大生成长度截断、任务本来还会继续，某些算法需要 bootstrap 下一状态估计。

本仓库 GAE 函数末尾使用 0，没有外部 bootstrap 参数。本课手算与当前函数保持一致；讨论其他轨迹设定时，不能把这个假定当作通用定理。

自查：先画状态/动作轴，再画 logits 移位轴，最后给 value 标状态含义。能够同时对齐这三件事，再继续研究完整训练中的采样策略分母与奖励质量。
