# 4. 预训练：把数据、模型和更新接成闭环

前置：[数据](2.DataLoader.md) 与 [模型](3.模型构建.md)。本章从“谁保存状态、谁计算梯度、什么时候更新”理解真实入口；逐行跟踪配合 [预训练循环精讲](0.预训练循环精讲.md)。

## 本章实践卡


完成标准：能分别说出 batch 数、optimizer 更新数、checkpoint 的 `step` 和 AdamW 状态里的 `step`，并能解释为什么第一批只有梯度没有参数更新。

## 1. 本章练的是同一台机器持续改进

```text
新建模型 W0
  第 1 批：计算 loss → 记下梯度，参数仍为 W0
  第 2 批：计算 loss → 累加梯度 → 更新为 W1 → 清空梯度
  第 3 批：计算 loss → 最后一组更新为 W2 → 清空梯度
保存 W2 与训练进度
```

“预训练”表示从连续文本构造下一个 token 任务，不表示必须使用某一种 GPU、学习率或固定训练天数。demo 训练用来验证流程，几条数据不产生可靠聊天能力。

### 为什么前两批可以用同一版参数

梯度累积先收集几份调整意见，再统一更新。第一批与第二批的前向都使用 W0，各自产生对 W0 的梯度；第二批结束把两份平均后执行一次更新。

```text
第 1 批：梯度 g1 / 2，写入 .grad
第 2 批：梯度 g2 / 2，累加后为 (g1+g2)/2
更新：AdamW 使用这份累计梯度、历史动量和当前 lr
第 3 批：新参数 W1 上计算 g3，尾组只有一批，所以除以 1
```

这不是先用 g1 改参数，再用 g2 改一次，也不是把各批 loss 的数值相加后不再保留计算路径。反向可以每批执行，`.grad` 负责累加。

当每批有效目标数不同时，“每批均值再平均”不等于把所有 token 的 loss 统一求平均。当前入口采用前者；只有每批监督规模一致等条件下，两者权重才相同。

## 2. 先读入口，再读单轮函数

| 位置 | 负责什么 | 断点观察 |
| --- | --- | --- |
| `__main__` 参数解析 | 决定实验条件 | `args` |
| 模型与优化器初始化 | 创建参数与更新历史 | `model`、`optimizer` |
| epoch 循环 | 为本轮设置采样顺序 | `epoch`、`loader` |
| `train_epoch()` | 逐批计算、累积、更新 | `X/Y/mask`、`loss`、`step` |
| `lm_checkpoint()` | 保存模型和进度 | `epoch`、batch `step`、优化器状态 |

模型和优化器在 epoch 循环外创建，不能每批重新初始化。当前函数依赖模块里的全局 model、optimizer 等对象，完整依赖说明见源码的函数注释。

### 哪些对象必须跨 batch 保留

| 对象 | 一批结束后的处理 | 原因 |
| --- | --- | --- |
| model 参数 | 保留 | 下一批使用当前学到的数值 |
| optimizer 状态 | 保留 | AdamW 的历史统计影响下一次更新 |
| 当前 X/Y/logits | 下一批替换 | 它们属于当前题目 |
| `.grad` | 累积组内保留，更新后清零 | 汇总同组贡献，避免跨组误累加 |
| sampler 顺序 | 按本轮设置 | 恢复时要找到同一批数据 |

如果把 `model = ...` 放进 batch 循环，每批都会回到新随机起点；若重建 AdamW，则会丢掉历史状态。能跑出 loss 不代表这个状态流正确。

## 3. 先用 CPU 看懂普通精度

本项目的辅助函数按下面的条件选择精度：

| 配置 | autocast | GradScaler |
| --- | --- | --- |
| CPU 或 float32 | 空上下文 | 关闭 |
| CUDA bfloat16 | 选择混合精度算子 | 关闭 |
| CUDA float16 | 选择混合精度算子 | 启用 |

float16 动态范围较小，梯度缩放用于减少下溢并处理非有限梯度。它不是训练正确性的保证，也不承诺固定速度提升。bfloat16 指数范围较大，但仍有精度和溢出方面的限制。

原文把 float16 最小正规数约 `6.1e-5` 当成所有正数的下限并不准确；它还支持更小的次正规数，具体算子对这些数的处理也需要考虑。不要据此断言“1e-6 的梯度必然全变成 0”。

当前代码使用项目 helper，而不是复制过时的 `torch.cuda.amp` 写法：

```python
autocast_ctx = autocast_context(device_type, dtype)
scaler = grad_scaler(device_type, dtype)

with autocast_ctx:
    res = model(X)
    loss = ...  # 按有效目标汇总，并按实际累积组大小缩放

scaler.scale(loss).backward()
```

完整累积组或最后一批时，再执行 `unscale_ → clip_grad_norm_ → step → update → zero_grad`。启用缩放时应先还原梯度再裁剪；每批都清零会破坏累积。

## 4. 学习率按当前公式手算一次

```python
def get_lr(current_step, total_steps, lr):
    return lr / 10 + 0.5 * lr * (1 + math.cos(math.pi * current_step / total_steps))
```

本函数只有余弦变化和常数下限项，没有实现 warmup，也没有 restart。它不是“所有项目的唯一标准”。

当 `lr=0.0005`、总进度为 3 个 batch：

| batch | 设置的 lr | 本次是否使用它更新 |
| --- | --- | --- |
| 1 | 0.000425 | 否，只累积 |
| 2 | 0.000175 | 是，第一次更新 |
| 3 | 0.000050 | 是，第二次更新 |

`current_step=0` 时该公式值为 `1.1*lr`，但本入口首次进度从 1 开始。warmup 是另一种可选调度机制，不是这个函数暗中包含的功能。

### 日志中的 lr 不等于每行都更新了一次

第 1 行显示 0.000425，但该批只积累梯度；第一次 AdamW 更新实际使用第 2 批设置的 0.000175。日志记当前 batch 的条件，不能只数日志行来数 optimizer steps。

梯度裁剪也不是学习率调度。前者控制累计梯度范数，后者设置更新尺度；AdamW 还会使用一阶、二阶历史与权重衰减，因此不能把所有参数变化都写成 `-lr*当前梯度`。

## 5. 恢复批数，用一叠纸就能算明白

假设一轮原有五批，已经完成前两批：

```text
原批号：   1  2  3  4  5
已完成：   ✓  ✓
剩余批号：       3  4  5

start_step = 2
len(剩余 loader) = 3
本轮总数 = 3 + 2 = 5
```

因此当前调用是：

```python
train_epoch(epoch, loader, len(loader) + start_step, start_step, wandb)
```

没有额外的 `+1`。`enumerate(..., start=start_step+1)` 给剩余三批编号 3、4、5；它不会凭空产生第六批。跳过数据由 `SkipBatchSampler` 完成，仅改变编号不能恢复数据进度。

checkpoint 的 step 已记录 batch 数，所以 `skip_batches=start_step`，不再乘梯度累积次数。恢复还需要保持数据、batch size、模型结构与相关配置一致；当前快照并不包含所有随机状态。

把这件事做成可重复实验：

```bash
.venv/bin/python scripts/lesson_lab.py --lesson resume
```

它先连续跑三批取得基准，再从头跑到 batch 2 完整保存后主动暂停，最后通过相同入口启用 `from_resume=1`。保持 epochs、max_steps 和学习率计划不变，预期看到“跳过前2个step，从step 3开始”，最终模型和 AdamW 状态与基准逐项一致。

暂停由实验代码在保存完成后抛出教学异常模拟，不需要手动强杀进程，也不修改已有权重。它不测试任意时刻断电、损坏文件或多卡恢复。

### 保存的是哪一种“现场”

只保存 W，类似只保存机器旋钮位置；完整续训还要知道已经处理哪批、优化器的历史和 scaler 状态。当前 checkpoint 不记录未更新的累计梯度，因此主入口把保存限制在更新边界。

`save_interval=1` 也不意味着在每个未完成的累积批次写出可精确续训快照。保存条件同时检查更新边界，最后一批则补做更新并保存。

更改 epochs 或 max_steps 会改变余弦调度的总进度。为了核对连续与恢复一致，应先保持计划不变，不是恢复时随手缩短总轮数。

## 6. DDP 与缓存清理放到第二遍学习

本课单进程 CPU 不进入 DDP 分支。DDP 主要在反向时同步参数梯度，默认行为还可能广播 buffer；它不是每次 step 都把模型参数和 buffer 一起 all-reduce。

源码保留了 `_ddp_params_and_buffers_to_ignore` 设置，但这属于实现相关细节，名称和 buffer 实际注册路径需要核对。RoPE 表的一次切片不会自动改变原 buffer 的形状。不能推断所有 RoPE 模型都必须加同一个私有属性才能训练。本机尚未完整验证多卡。

`empty_cache()` 释放未占用 CUDA 缓存，不会释放仍被参数和计算图引用的张量。CPU 练习不需要它；模型实际需求超过显存时，也不能仅靠频繁调用它解决。

### 训练前后先用固定题目比较

保留同一条输入、同一 tokenizer、同一生成方式，分别在训练前后记录目标 loss 和输出。不同 batch 的日志下降，可能来自题目难度变化；一次随机采样的改善，也不能代表整体任务性能。

自查题：把 accumulation 从 2 改成 1，三批会更新几次？答案是三次，checkpoint 的 batch step 仍为 3。再改回 2，解释为什么尾组不等待不存在的第 4 批。

## 8. 打开真实 checkpoint，看见训练记忆

AdamW 除了 W，还保存每个参数对应的一阶、二阶历史。它们不是新的模型层，而是优化器下次如何调整这张参数表的依据。

| 保存项 | 示例含义 | 是否用于普通前向 |
| --- | --- | --- |
| model | E、投影、Norm 等当前数值 | 是 |
| optimizer.state.step | 已执行更新次数 | 否 |
| exp_avg | 梯度的一阶历史 | 否 |
| exp_avg_sq | 梯度平方的历史 | 否 |
| epoch / step | 数据进度 | 否 |
| scaler | 混合精度缩放状态 | 否 |

```python
# doc-example: checkpoint-contents
import tempfile
from pathlib import Path
import torch
from scripts.lesson_lab import run_pretrain
from trainer.train_utils import torch_load

with tempfile.TemporaryDirectory(prefix="pretrain_states_") as directory:
    checkpoint = run_pretrain(directory)
    assert checkpoint["step"] == 3
    states = list(checkpoint["optimizer"]["state"].values())
    assert states and {int(s["step"].item()) for s in states} == {2}
    first = states[0]
    assert first["exp_avg"].shape == first["exp_avg_sq"].shape
    inference_weight = torch_load(Path(directory) / "out/pretrain_128.pth")
    assert next(iter(inference_weight.values())).dtype == torch.float16
    assert next(iter(checkpoint["model"].values())).dtype == torch.float32
    print("batch step / AdamW step：", checkpoint["step"], first["step"].item())
    print("首个参数的优化历史形状：", first["exp_avg"].shape)
```

主入口给推理文件的副本转半精度，没有把内存中的训练参数变成半精度。resume 中保留的训练数值与优化器状态用于更完整的恢复；只有推理文件不能还原 AdamW 历史。

### 保留一次可继续学习的 128 维训练

章节实验的临时文件会清理。想保留文件供后续 SFT 使用，可以直接运行：

```bash
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 .venv/bin/python -m trainer.train_pretrain \
  --device cpu --dtype float32 --hidden_size 128 --num_hidden_layers 2 \
  --data_path dataset/demo_pretrain.jsonl --max_seq_len 64 \
  --epochs 1 --batch_size 1 --num_workers 0 --accumulation_steps 2 \
  --max_steps 3 --from_weight none --from_resume 0 \
  --save_dir out/pretrain_lesson --checkpoint_dir checkpoints/pretrain_lesson \
  --log_interval 1 --save_interval 2
```

这组目录与 VS Code 的 `out/debug_accum` 不同；后续 SFT 若使用本组权重，需同步更改基础权重目录，不能照抄另一条路径。

完成标准：在 checkpoint 中找到一张模型权重、同形状优化器历史、batch step=3 与更新 step=2，解释这四件事为何并不冲突。
