## 0. 预训练到底是什么

预训练是模型的基础接龙练习：**从连续正文自动构造“根据前文预测下一片 token”的任务**。

例如原文开头被 tokenizer 切成：

```text
文字片段： M    in    i    M    ind
token ID：47   261   75   47   807
```

Dataset 将它错开一位：

```text
X：47   261   75   47   807 ...
Y：261   75   47   807   370 ...
```

于是自动得到多道接龙题：

| 输入 X | 目标 Y |
| --- | --- |
| `M` | `in` |
| `M in` | `i` |
| `M in i` | `M` |
| `M in i M` | `ind` |
| `MiniMind` | ` is` |

这里的答案来自原文的下一个 token，不需要人工为每道题写标签，所以它属于**自监督学习**。模型通过：

```text
X/Y
→ Embedding、Attention、FFN、lm_head
→ logits
→ 交叉熵 loss
→ backward 得到梯度
→ AdamW 更新参数
```

逐渐学习 token 的衔接、语法、上下文关系和语料中的统计规律。几条 demo 只用于验证流程，不能代表模型已经获得可靠语言能力。

## 1. 本章练的是同一台机器持续改进

```text
新建模型 W0
  第 1 批：计算 loss → 记下梯度，参数仍为 W0
  第 2 批：计算 loss → 累加梯度 → 更新为 W1 → 清空梯度
  第 3 批：计算 loss → 最后一组更新为 W2 → 清空梯度
保存 W2 与训练进度
```

“预训练”表示从连续文本构造下一个 token 任务，不表示必须使用某一种 GPU、学习率或固定训练天数。demo 训练用来验证流程，几条数据不产生可靠聊天能力。

### 为什么前两批可以用同一版参数

梯度累积先收集几份调整意见，再统一更新。第一批与第二批的前向都使用 W0，各自产生对 W0 的梯度；第二批结束把两份平均后执行一次更新。

```text
第 1 批：梯度 g1 / 2，写入 .grad
第 2 批：梯度 g2 / 2，累加后为 (g1+g2)/2
更新：AdamW 使用这份累计梯度、历史动量和当前 lr
第 3 批：新参数 W1 上计算 g3，尾组只有一批，所以除以 1
```

这不是先用 g1 改参数，再用 g2 改一次，也不是把各批 loss 的数值相加后不再保留计算路径。反向可以每批执行，`.grad` 负责累加。

当每批有效目标数不同时，“每批均值再平均”不等于把所有 token 的 loss 统一求平均。当前入口采用前者；只有每批监督规模一致等条件下，两者权重才相同。

### 三个 batch 为什么只有两次参数更新

本课配置是：

```text
batch 数 = 3
accumulation_steps = 2
```

因此时间线是：

| batch | backward 后的梯度 | 是否 `optimizer.step()` | 参数版本 |
| --- | --- | --- | --- |
| 1 | `g1 / 2` | 否 | `W0` |
| 2 | `g1/2 + g2/2` | 是，第 1 次 | `W0 → W1` |
| 3 | `g3 / 1`，本轮尾组 | 是，第 2 次 | `W1 → W2` |

所以日志里的 `(1/3)(2/3)(3/3)` 表示处理了三批；AdamW 的状态 `step=2` 表示参数更新了两次。若 `accumulation_steps=1`，三批会更新三次。

最后一批必须更新，即使没有凑够两批；否则最后一批的梯度会被留在内存中而没有用于本轮训练。

## 2. 先读入口，再读单轮函数

| 位置 | 负责什么 | 断点观察 |
| --- | --- | --- |
| `__main__` 参数解析 | 决定实验条件 | `args` |
| 模型与优化器初始化 | 创建参数与更新历史 | `model`、`optimizer` |
| epoch 循环 | 为本轮设置采样顺序 | `epoch`、`loader` |
| `train_epoch()` | 逐批计算、累积、更新 | `X/Y/mask`、`loss`、`step` |
| `lm_checkpoint()` | 保存模型和进度 | `epoch`、batch `step`、优化器状态 |

模型和优化器在 epoch 循环外创建，不能每批重新初始化。当前函数依赖模块里的全局 model、optimizer 等对象，完整依赖说明见源码的函数注释。

### 哪些对象必须跨 batch 保留

| 对象 | 一批结束后的处理 | 原因 |
| --- | --- | --- |
| model 参数 | 保留 | 下一批使用当前学到的数值 |
| optimizer 状态 | 保留 | AdamW 的历史统计影响下一次更新 |
| 当前 X/Y/logits | 下一批替换 | 它们属于当前题目 |
| `.grad` | 累积组内保留，更新后清零 | 汇总同组贡献，避免跨组误累加 |
| sampler 顺序 | 按本轮设置 | 恢复时要找到同一批数据 |

如果把 `model = ...` 放进 batch 循环，每批都会回到新随机起点；若重建 AdamW，则会丢掉历史状态。能跑出 loss 不代表这个状态流正确。

### `forward → loss → backward` 到底在做什么

可以把一次训练想成学生完成、老师评分、老师反向指出修改方向：

```text
forward：学生先答题，写出每道题对所有选项的分数
loss：    老师拿标准答案检查，汇总这次答得有多差
backward：老师沿着答题过程倒着追踪，告诉每个旋钮应该往哪边调
```

这三步都还没有真正修改模型参数。参数真正改变要等后面的：

```text
optimizer.step()
```

#### 第一步：forward，模型先完成一次预测

当前真实 batch 的输入是：

```text
X.shape = [1,63]
```

含义是 1 条样本、63 个输入位置，每个位置是一个整数 token ID。模型前向大致经过：

```text
X [1,63]
  ↓ Embedding 查表
hidden [1,63,128]
  ↓ 两层 Transformer Block
hidden [1,63,128]
  ↓ lm_head
logits [1,63,6400]
```

例如第 0 个位置：

```text
X[0,0] = 47，片段是 "M"
Y[0,0] = 261，片段是 "in"
```

模型并不是直接输出 `"in"`，而是输出一排 6400 个原始分数：

```text
logits[0,0,:]  # 6400 个候选 token 的分数
```

第 261 项就是模型对 `"in"` 的分数。当前随机初始化实验中，这个分数约为 `0.382358`，但模型还同时为另外 6399 个候选打分。

forward 的本质是：

```python
res = model(X)
logits = res.logits
```

它建立了一张自动求导计算图，记录每个输出是怎样由 Embedding、Attention、FFN、lm_head 和参数计算出来的。此时：

```python
model.lm_head.weight.grad is None
```

是正常的，因为还没有执行 backward。

#### 第二步：loss，拿预测与标准答案评分

模型输出的是 `[1,63,6400]`，但每个位置的标准答案只有一个 ID，因此把它理解为 63 道选择题：

```text
63 道题，每道题有 6400 个选项
Y[0,t] 指出第 t 道题的正确选项
```

代码先把 batch 轴和位置轴合并：

```text
logits：[1,63,6400] -> [63,6400]
Y：     [1,63]       -> [63]
```

每一行计算一次交叉熵，再恢复为：

```text
per_token_loss：[63] -> [1,63]
```

第 0 个位置的交叉熵可以写成：

```text
loss[0,0] = -log(softmax(logits[0,0])[261])
```

它问的是：“模型给正确答案 `in` 分了多少概率？”正确答案概率越低，loss 越大。

当前第 0 个位置的实测值约为：

```text
目标 logit：0.382358
目标概率：  0.00019090
位置 loss： 8.563768
```

注意：`0.382358` 是原始分数，`0.00019090` 才是 softmax 后的概率，`8.563768` 是负对数损失。三个数字不是同一个东西。

本批有 63 个位置，但只有 19 个目标有效。padding 位置由 `loss_mask=0` 排除：

```python
loss = (per_token_loss * loss_mask).sum()
loss = loss / loss_mask.sum()
```

所以本批 loss 是 19 个有效位置的平均，不是 63 个位置的平均，也不是只看第 0 个位置。

#### 第三步：backward，沿计算图倒着追责

调用：

```python
loss.backward()
```

可以想象成老师拿着最终总分，沿着答题过程倒着追问：

```text
总 loss 变大，是哪些 logits 造成的？
这些 logits，是哪些 hidden 特征造成的？
这些 hidden 特征，又是哪些 Attention、FFN 和 Embedding 参数造成的？
```

数学上就是链式法则：

```text
loss
 ↓ ∂loss/∂logits
hidden states
 ↓ ∂loss/∂hidden
Attention / FFN / Embedding 参数
 ↓
parameter.grad
```

以最终词表打分为例：

```text
logits = h @ E.T
```

如果某个候选的分数让 loss 变大，backward 会计算：

```text
loss 对 h 的梯度
loss 对 E 的梯度
```

然后继续穿过第二层 Block、第一层 Block，最终给各个参数写入 `.grad`。

backward 做的是“记录修改建议”，不是直接拧参数：

| 时刻 | 参数 | `.grad` |
|---|---|---|
| forward 后 | 原值 W0 | `None` |
| backward 后 | 仍为 W0 | 已有梯度 |
| optimizer.step 后 | 变成 W1 | 梯度已被使用 |
| zero_grad 后 | 保留 W1 | `None` 或清零 |

因此下面的检查应该成立：

```python
before = model.lm_head.weight.detach().clone()
loss.backward()
torch.testing.assert_close(model.lm_head.weight, before)
assert model.lm_head.weight.grad is not None
```

只有后面的：

```python
optimizer.step()
```

才会根据梯度、学习率、AdamW 的历史状态和权重衰减，把 W0 改成新的 W1。

#### 为什么 backward 之后要清理计算图和梯度

当前每个 batch 都会建立一张新的计算图。完成 backward 后，上一批的中间激活通常不再需要；如果不清理梯度：

```text
本批梯度 + 下一批梯度
```

就会继续累积。梯度累积训练故意保留它到更新边界；执行 `optimizer.step()` 后则调用：

```python
optimizer.zero_grad(set_to_none=True)
```

把已经使用过的建议清掉，准备下一组 batch。

当前三批实验的完整顺序是：

```text
batch 1：
  forward → loss → backward
  参数不变，保留 g1/2

batch 2：
  forward → loss → backward
  累积 g1/2 + g2/2
  optimizer.step → 参数更新
  zero_grad

batch 3：
  forward → loss → backward
  optimizer.step → 尾组更新
  zero_grad
```

**自查**：如果只执行 forward，为什么没有 `.grad`？如果执行 backward 后参数为什么还没变？如果执行 step 后为什么必须重新 forward 才能评价新参数？能回答这三个问题，就真正理解了这条训练主线。

## 3. 先用 CPU 看懂普通精度

本项目的辅助函数按下面的条件选择精度：

| 配置 | autocast | GradScaler |
| --- | --- | --- |
| CPU 或 float32 | 空上下文 | 关闭 |
| CUDA bfloat16 | 选择混合精度算子 | 关闭 |
| CUDA float16 | 选择混合精度算子 | 启用 |

float16 动态范围较小，梯度缩放用于减少下溢并处理非有限梯度。它不是训练正确性的保证，也不承诺固定速度提升。bfloat16 指数范围较大，但仍有精度和溢出方面的限制。

原文把 float16 最小正规数约 `6.1e-5` 当成所有正数的下限并不准确；它还支持更小的次正规数，具体算子对这些数的处理也需要考虑。不要据此断言“1e-6 的梯度必然全变成 0”。

当前代码使用项目 helper，而不是复制过时的 `torch.cuda.amp` 写法：

```python
autocast_ctx = autocast_context(device_type, dtype)
scaler = grad_scaler(device_type, dtype)

with autocast_ctx:
    res = model(X)
    loss = ...  # 按有效目标汇总，并按实际累积组大小缩放

scaler.scale(loss).backward()
```

完整累积组或最后一批时，再执行 `unscale_ → clip_grad_norm_ → step → update → zero_grad`。启用缩放时应先还原梯度再裁剪；每批都清零会破坏累积。

### AMP：改变计算精度，不改变训练目标

AMP 是 **Automatic Mixed Precision，自动混合精度**。它让适合的算子使用较低精度，以节省显存并提高 GPU 计算速度；它不改变 X、Y、loss 的定义，也不改变模型的层结构。

当前仓库的条件是：

| 配置 | autocast | GradScaler |
| --- | --- | --- |
| CPU / float32 | 关闭 | 关闭 |
| CUDA / bfloat16 | 开启 | 关闭 |
| CUDA / float16 | 开启 | 开启 |

`autocast` 负责选择算子精度；`GradScaler` 主要防止 float16 梯度下溢。启用缩放时，必须先：

```text
scale(loss).backward()
→ unscale_(optimizer)
→ clip_grad_norm_
→ scaler.step(optimizer)
→ scaler.update()
```

本课 CPU 实验没有真正使用 AMP，因此可先按普通 float32 理解全部数值，再切换到 CUDA 检查混合精度的边界。

### DDP：多份完整模型并行处理不同数据

DDP 是 **DistributedDataParallel，分布式数据并行**。每个进程通常拥有一份完整模型，各自读取不同数据分片：

```text
GPU 0：完整模型 + 数据 A/B
GPU 1：完整模型 + 数据 C/D
              ↓ backward 后同步梯度
        各进程保持相同参数并更新
```

DDP 不是把模型的不同层拆到不同 GPU；它解决的是多 GPU 并行训练。AMP 解决计算精度，DDP 解决设备之间的数据和梯度同步，两者可以组合使用。

本仓库的 CPU 教学没有真正启动 DDP。单卡路径使用 `DistributedSampler(num_replicas=1)`，只是为了复用确定性采样逻辑，不代表已经启动多卡进程。完整多卡训练不由本课的 CPU 实验覆盖。

## 4. 学习率按当前公式手算一次

```python
def get_lr(current_step, total_steps, lr):
    return lr / 10 + 0.5 * lr * (1 + math.cos(math.pi * current_step / total_steps))
```

本函数只有余弦变化和常数下限项，没有实现 warmup，也没有 restart。它不是“所有项目的唯一标准”。

当 `lr=0.0005`、总进度为 3 个 batch：

| batch | 设置的 lr | 本次是否使用它更新 |
| --- | --- | --- |
| 1 | 0.000425 | 否，只累积 |
| 2 | 0.000175 | 是，第一次更新 |
| 3 | 0.000050 | 是，第二次更新 |

`current_step=0` 时该公式值为 `1.1*lr`，但本入口首次进度从 1 开始。warmup 是另一种可选调度机制，不是这个函数暗中包含的功能。

### 日志中的 lr 不等于每行都更新了一次

第 1 行显示 0.000425，但该批只积累梯度；第一次 AdamW 更新实际使用第 2 批设置的 0.000175。日志记当前 batch 的条件，不能只数日志行来数 optimizer steps。

梯度裁剪也不是学习率调度。前者控制累计梯度范数，后者设置更新尺度；AdamW 还会使用一阶、二阶历史与权重衰减，因此不能把所有参数变化都写成 `-lr*当前梯度`。

## 5. 恢复批数，用一叠纸就能算明白

假设一轮原有五批，已经完成前两批：

```text
原批号：   1  2  3  4  5
已完成：   ✓  ✓
剩余批号：       3  4  5

start_step = 2
len(剩余 loader) = 3
本轮总数 = 3 + 2 = 5
```

因此当前调用是：

```python
train_epoch(epoch, loader, len(loader) + start_step, start_step, wandb)
```

没有额外的 `+1`。`enumerate(..., start=start_step+1)` 给剩余三批编号 3、4、5；它不会凭空产生第六批。跳过数据由 `SkipBatchSampler` 完成，仅改变编号不能恢复数据进度。

checkpoint 的 step 已记录 batch 数，所以 `skip_batches=start_step`，不再乘梯度累积次数。恢复还需要保持数据、batch size、模型结构与相关配置一致；当前快照并不包含所有随机状态。

### 恢复为什么必须跳过旧数据

假设 batch 1、2 已经训练并保存：

```text
第一次运行：batch 1 → batch 2 → 保存
重新启动：  如果从头读取，就会再次得到 batch 1、batch 2、batch 3
```

模型参数已经包含 batch 1、2 的更新，若再次读取它们，就会重复训练旧数据。正确恢复需要：

```text
读取 checkpoint 的 step=2
→ set_epoch(epoch)，重建同一轮的采样顺序
→ SkipBatchSampler 丢弃前 2 个完整 batch
→ enumerate 从 step=3 开始编号
→ 只处理 batch 3
```

仅把 `enumerate(..., start=3)` 改成 3 只会改变显示编号，不会跳过数据；真正跳过数据的是 `SkipBatchSampler`。当前受控实验验证了连续训练与恢复训练的模型、AdamW 状态一致，但 checkpoint 没有保存所有随机状态和 DataLoader worker 状态。

把这件事做成可重复实验：

```bash
.venv/bin/python scripts/lesson_lab.py --lesson resume
```

它先连续跑三批取得基准，再从头跑到 batch 2 完整保存后主动暂停，最后通过相同入口启用 `from_resume=1`。保持 epochs、max_steps 和学习率计划不变，预期看到“跳过前2个step，从step 3开始”，最终模型和 AdamW 状态与基准逐项一致。

暂停由实验代码在保存完成后抛出教学异常模拟，不需要手动强杀进程，也不修改已有权重。它不测试任意时刻断电、损坏文件或多卡恢复。

### 保存的是哪一种“现场”

只保存 W，类似只保存机器旋钮位置；完整续训还要知道已经处理哪批、优化器的历史和 scaler 状态。当前 checkpoint 不记录未更新的累计梯度，因此主入口把保存限制在更新边界。

`save_interval=1` 也不意味着在每个未完成的累积批次写出可精确续训快照。保存条件同时检查更新边界，最后一批则补做更新并保存。

更改 epochs 或 max_steps 会改变余弦调度的总进度。为了核对连续与恢复一致，应先保持计划不变，不是恢复时随手缩短总轮数。

## 6. DDP 与缓存清理放到第二遍学习

本课单进程 CPU 不进入 DDP 分支。DDP 主要在反向时同步参数梯度，默认行为还可能广播 buffer；它不是每次 step 都把模型参数和 buffer 一起 all-reduce。

源码保留了 `_ddp_params_and_buffers_to_ignore` 设置，但这属于实现相关细节，名称和 buffer 实际注册路径需要核对。RoPE 表的一次切片不会自动改变原 buffer 的形状。不能推断所有 RoPE 模型都必须加同一个私有属性才能训练。本机尚未完整验证多卡。

`empty_cache()` 释放未占用 CUDA 缓存，不会释放仍被参数和计算图引用的张量。CPU 练习不需要它；模型实际需求超过显存时，也不能仅靠频繁调用它解决。

## 8. 打开真实 checkpoint，看见训练记忆

AdamW 除了 W，还保存每个参数对应的一阶、二阶历史。它们不是新的模型层，而是优化器下次如何调整这张参数表的依据。

| 保存项 | 示例含义 | 是否用于普通前向 |
| --- | --- | --- |
| model | E、投影、Norm 等当前数值 | 是 |
| optimizer.state.step | 已执行更新次数 | 否 |
| exp_avg | 梯度的一阶历史 | 否 |
| exp_avg_sq | 梯度平方的历史 | 否 |
| epoch / step | 数据进度 | 否 |
| scaler | 混合精度缩放状态 | 否 |

```python
# doc-example: checkpoint-contents
import tempfile
from pathlib import Path
import torch
from scripts.lesson_lab import run_pretrain
from trainer.train_utils import torch_load

with tempfile.TemporaryDirectory(prefix="pretrain_states_") as directory:
    checkpoint = run_pretrain(directory)
    assert checkpoint["step"] == 3
    states = list(checkpoint["optimizer"]["state"].values())
    assert states and {int(s["step"].item()) for s in states} == {2}
    first = states[0]
    assert first["exp_avg"].shape == first["exp_avg_sq"].shape
    inference_weight = torch_load(Path(directory) / "out/pretrain_128.pth")
    assert next(iter(inference_weight.values())).dtype == torch.float16
    assert next(iter(checkpoint["model"].values())).dtype == torch.float32
    print("batch step / AdamW step：", checkpoint["step"], first["step"].item())
    print("首个参数的优化历史形状：", first["exp_avg"].shape)
```

主入口给推理文件的副本转半精度，没有把内存中的训练参数变成半精度。resume 中保留的训练数值与优化器状态用于更完整的恢复；只有推理文件不能还原 AdamW 历史。
