# 13. 强化学习数学附录：先手算，再找实现

这是 [PPO](7.PPO.md)、[DPO](8.DPO.md) 与 [GRPO](11.GRPO.md) 的第二遍阅读材料，不要求初学者在训练前记住全部推导。下面的教学函数用于解释公式；真实入口行为以链接到的源码为准。

## 1. 把同一个符号放到生成过程里

```text
问题 + 已生成前文：状态 s_t
接下来生成的 token：动作 a_t
语言模型：策略 pi(a_t | s_t)
外部给分：reward r_t
预计后续回报：value V(s_t)
比当前基线好多少：advantage A_t
```

生成了 `a_t` 之后，状态变为包含这个 token 的新上下文。value 的状态对齐、奖励落在哪个 token 和 done 标记，决定公式是否与代码匹配，不能只看维度都为 `[B,T]`。

## 2. GAE：把后面的反馈折回前面

有限轨迹带终止标记的递推：

$$
\delta_t=r_t+\gamma(1-d_t)V_{t+1}-V_t
$$

$$
A_t=\delta_t+\gamma\lambda(1-d_t)A_{t+1}
$$

设 gamma=lambda=1，奖励 `[0,0,1]`，value `[0.2,0.3,0.4]`，最后一项 done=1，则 delta=`[0.1,0.1,0.6]`，倒序 A=`[0.8,0.7,0.6]`，returns=A+V=`[1,1,1]`。

这解释为什么要倒序算：A0 需要 A1，A1 又需要 A2。对应真实 `GAE` 类在 [train_ppo.py](../trainer/train_ppo.py)。

无限和的简写为 `A_t = Σ_l (gamma*lambda)^l * delta_(t+l)`。有限轨迹需要终止与 bootstrap 条件，不能直接把无限几何级数步骤搬过去丢掉 lambda 次幂。

lambda=0 只保留当前 TD 残差；lambda=1 更接近带折扣回报减 value 的形式，具体是否无偏还取决于终止、截断和价值估计，不能只凭这个参数作绝对结论。

## 3. PPO 策略损失：为什么正负优势要分别算

```python
ratio = (new_logp - behavior_logp).exp()
plain = ratio * advantage
clipped = ratio.clamp(1 - epsilon, 1 + epsilon) * advantage
loss = -torch.minimum(plain, clipped)
```

取 epsilon=0.2：

| ratio | A | plain | clipped | 最终 loss |
| --- | --- | --- | --- | --- |
| 1.5 | 1 | 1.5 | 1.2 | -1.2 |
| 0.5 | 1 | 0.5 | 0.8 | -0.5 |
| 1.5 | -1 | -1.5 | -1.2 | 1.5 |
| 0.5 | -1 | -0.5 | -0.8 | 0.8 |

观察正负 A 后裁剪的限制方向。它没有直接限制所有参数步长，也不能修复行为策略分母记录错误。当前 PPO 的 Old Actor 同步机制与采样分母问题见第 7 章。

## 4. Value loss：预测与实际回报的距离

基础形式是：

$$
L_V=\frac12(V_\phi(s_t)-R_t)^2.
$$

预测 0.3、目标 1 时，损失为 0.245。目标通常来自回报估计，并不是“奖励模型直接给每个位置都打了 1 分”。

可选的 clipped value 教学表达式：

```python
limited = old_value + (value - old_value).clamp(-epsilon, epsilon)
loss = 0.5 * torch.maximum((value - returns).square(),
                           (limited - returns).square())
```

clamp 下限必须是 `-epsilon`，不能上下限都写 `epsilon`。这只是可选形式；当前 PPO 入口使用的是 masked MSE，没有使用上述 clipped value 公式。

## 5. 奖励模型：好回答分数应该相对更高

成对评分的一种目标：

```python
loss = -F.logsigmoid(chosen_reward - rejected_reward)
```

分差为 0 时 loss≈0.693；分差为 1 时≈0.313；分差为 -1 时≈1.313。这里学习的是标注偏好关系，不是让 reward 自动成为校准过的真实性概率。

可选 margin 用 `chosen-rejected-margin`，应明确判断 `margin is not None`，不要把多元素 tensor 直接放进 `if margin:`。本项目 PPO/GRPO 加载外部奖励模型，本章公式不代表仓库实现了奖励模型训练入口。

## 6. log probability 差为什么可能为负

同一 token 的概率 P=0.1、Q=0.2：

```text
log(P)-log(Q) = log(0.5) ≈ -0.693
```

单个位置负数完全正常。真正的离散 KL 是 `Σ P*(log P-log Q)`，按 P 加权后非负；一个样本上的差不能直接叫完整 KL。

把样本平均视为 KL 估计需要对应采样分布。再把该估计当优化目标时，梯度是否与想要的 KL 目标一致还涉及采样和停止梯度处理，不能无条件从“无偏数值估计”推断“无偏目标梯度”。

GRPO 当前使用的 `exp(d)-d-1` 逐样本非负，其中 `d=ref_logp-logp`。它在某一 token 上等于零，不保证两个完整词表分布一致。

## 7. DPO：相对偏好差的差

设 chosen/rejected 的汇总 log probability 为：

```text
Policy：    -1 / -2 -> 差值 1
Reference： -2 / -2 -> 差值 0
相对提升 delta = 1-0 = 1
loss = -logsigmoid(beta*delta)
```

beta=0.1 时 loss≈0.644397。Policy 和 Reference 相同则 delta=0、loss≈0.693147。

原始序列 DPO 通常使用 token log probability 之和，本仓库使用按 mask 长度平均后的分数。取平均是改变目标，不应把它写成整句 log probability 的等式。详见 [DPO](8.DPO.md)。

## 8. GRPO：先分组，再理解 detach

奖励 `[1,2,3]` 在同题组内标准化为约 `[-1,0,1]`。当前代码还做全 batch 再标准化，因此要按阶段比较变量。

```python
x = torch.tensor([-0.5], requires_grad=True)
ratio = torch.exp(x - x.detach())  # 数值为 1
ratio.sum().backward()            # x.grad 为 1
```

detach 项在这次计算图里视为常数，因此有梯度。用这个表达式不等于存储了旧策略概率；当前 GRPO 入口也没有第 3 节那样的历史比率裁剪。
