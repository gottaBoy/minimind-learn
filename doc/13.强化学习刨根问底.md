# 13. 强化学习数学附录：先手算，再找实现

## 1. 把同一个符号放到生成过程里

```text
问题 + 已生成前文：状态 s_t
接下来生成的 token：动作 a_t
语言模型：策略 pi(a_t | s_t)
外部给分：reward r_t
预计后续回报：value V(s_t)
比当前基线好多少：advantage A_t
```

生成了 `a_t` 之后，状态变为包含这个 token 的新上下文。value 的状态对齐、奖励落在哪个 token 和 done 标记，决定公式是否与代码匹配，不能只看维度都为 `[B,T]`。

### 先把动作前后的时间轴画开

```text
状态 s0 --选 a0--> 状态 s1 --选 a1--> 状态 s2 --选 a2--> 终止
   V0      r0        V1      r1        V2      r2
```

V(s_t) 预测从当前状态继续的回报；r_t 是采取动作后收到的即时反馈。语言模型 logits 所在位置与动作 ID 错开一位，Critic 的状态切片也需要按这条时间轴明确。

每次看 `[B,T]`，先写下 T 是输入 token、动作、状态还是补齐后的生成长度。形状一样不意味着时间语义相同。

## 2. GAE：把后面的反馈折回前面

有限轨迹带终止标记的递推：

$$
\delta_t=r_t+\gamma(1-d_t)V_{t+1}-V_t
$$

$$
A_t=\delta_t+\gamma\lambda(1-d_t)A_{t+1}
$$

设 gamma=lambda=1，奖励 `[0,0,1]`，value `[0.2,0.3,0.4]`，最后一项 done=1，则 delta=`[0.1,0.1,0.6]`，倒序 A=`[0.8,0.7,0.6]`，returns=A+V=`[1,1,1]`。

这解释为什么要倒序算：A0 需要 A1，A1 又需要 A2。对应真实 `GAE` 类在 [train_ppo.py](../trainer/train_ppo.py)。

无限和的简写为 `A_t = Σ_l (gamma*lambda)^l * delta_(t+l)`。有限轨迹需要终止与 bootstrap 条件，不能直接把无限几何级数步骤搬过去丢掉 lambda 次幂。

lambda=0 只保留当前 TD 残差；lambda=1 更接近带折扣回报减 value 的形式，具体是否无偏还取决于终止、截断和价值估计，不能只凭这个参数作绝对结论。

### 把三步递推展开，检查每个幂次

若中途没有终止：

```text
A2 = delta2
A1 = delta1 + gamma*lambda*delta2
A0 = delta0 + gamma*lambda*delta1 + (gamma*lambda)^2*delta2
```

远处的残差同时受到 gamma 与 lambda 的幂次影响，不能只给 gamma 加幂。终止标记则会切断跨越终点的项。

```python
# doc-example: gae-discount-powers
import numpy as np
from trainer.train_ppo import GAE

reward = np.array([[0., 0., 1.]], dtype=np.float32)
value = np.array([[.2, .3, .4]], dtype=np.float32)
done = np.array([[0., 0., 1.]], dtype=np.float32)
gamma, lam = .9, .8
delta = np.array([.07, .06, .6])
expected_a0 = delta[0] + gamma * lam * delta[1] + (gamma * lam)**2 * delta[2]
actual = GAE(1, 3, gamma=gamma, lambda_=lam)(done, reward, value)
np.testing.assert_allclose(actual, [[expected_a0, .492, .6]], atol=1e-6)
print("带折扣与 lambda 的优势：", actual)
```

此时 A+V 不是每项都为 1；这是带折扣与优势估计后的回报目标，不应继续照抄 gamma=lambda=1 时的表。

## 3. PPO 策略损失：为什么正负优势要分别算

```python
ratio = (new_logp - behavior_logp).exp()
plain = ratio * advantage
clipped = ratio.clamp(1 - epsilon, 1 + epsilon) * advantage
loss = -torch.minimum(plain, clipped)
```

取 epsilon=0.2：

| ratio | A | plain | clipped | 最终 loss |
| --- | --- | --- | --- | --- |
| 1.5 | 1 | 1.5 | 1.2 | -1.2 |
| 0.5 | 1 | 0.5 | 0.8 | -0.5 |
| 1.5 | -1 | -1.5 | -1.2 | 1.5 |
| 0.5 | -1 | -0.5 | -0.8 | 0.8 |

观察正负 A 后裁剪的限制方向。它没有直接限制所有参数步长，也不能修复行为策略分母记录错误。当前 PPO 的 Old Actor 同步机制与采样分母问题见第 7 章。

### 用梯度验证“鼓励”和“惩罚”的符号

```python
# doc-example: policy-gradient-signs
import torch

new_logp = torch.tensor([-0.5, -0.5], requires_grad=True)
behavior_logp = new_logp.detach().clone()
advantage = torch.tensor([1., -1.])
ratio = (new_logp - behavior_logp).exp()
loss = -torch.minimum(ratio * advantage, ratio.clamp(.8, 1.2) * advantage).mean()
loss.backward()
torch.testing.assert_close(new_logp.grad, torch.tensor([-.5, .5]))
print("正优势提高动作 logp，负优势降低动作 logp：", new_logp.grad)
```

这是对独立 logp 的导数；真实网络的参数同时影响多个 token 和候选。不要把某个坐标的期望方向写成一次复杂优化后所有概率的保证。

## 4. Value loss：预测与实际回报的距离

基础形式是：

$$
L_V=\frac12(V_\phi(s_t)-R_t)^2.
$$

预测 0.3、目标 1 时，损失为 0.245。目标通常来自回报估计，并不是“奖励模型直接给每个位置都打了 1 分”。

可选的 clipped value 教学表达式：

```python
limited = old_value + (value - old_value).clamp(-epsilon, epsilon)
loss = 0.5 * torch.maximum((value - returns).square(),
                           (limited - returns).square())
```

clamp 下限必须是 `-epsilon`，不能上下限都写 `epsilon`。这只是可选形式；当前 PPO 入口使用 masked MSE，且没有乘上面基础公式的 1/2，因此预测 0.3、目标 1 的该项是 0.49，不是 0.245。它也没有使用上述 clipped value 公式。

## 5. 奖励模型：好回答分数应该相对更高

成对评分的一种目标：

```python
loss = -F.logsigmoid(chosen_reward - rejected_reward)
```

分差为 0 时 loss≈0.693；分差为 1 时≈0.313；分差为 -1 时≈1.313。这里学习的是标注偏好关系，不是让 reward 自动成为校准过的真实性概率。

可选 margin 用 `chosen-rejected-margin`，应明确判断 `margin is not None`，不要把多元素 tensor 直接放进 `if margin:`。本项目 PPO/GRPO 加载外部奖励模型，本章公式不代表仓库实现了奖励模型训练入口。

## 6. log probability 差为什么可能为负

同一 token 的概率 P=0.1、Q=0.2：

```text
log(P)-log(Q) = log(0.5) ≈ -0.693
```

单个位置负数完全正常。真正的离散 KL 是 `Σ P*(log P-log Q)`，按 P 加权后非负；一个样本上的差不能直接叫完整 KL。

把样本平均视为 KL 估计需要对应采样分布。再把该估计当优化目标时，梯度是否与想要的 KL 目标一致还涉及采样和停止梯度处理，不能无条件从“无偏数值估计”推断“无偏目标梯度”。

GRPO 当前使用的 `exp(d)-d-1` 逐样本非负，其中 `d=ref_logp-logp`。它在某一 token 上等于零，不保证两个完整词表分布一致。

### 数值估计与梯度估计为什么要分别检查

```python
# doc-example: kl-expectations
import torch

p = torch.tensor([0.8, 0.2])
q = torch.tensor([0.5, 0.5])
sample_difference = p.log() - q.log()
kl = (p * sample_difference).sum()
d = q.log() - p.log()
nonnegative_estimator = d.exp() - d - 1
assert sample_difference[1] < 0
assert (nonnegative_estimator >= 0).all() and kl > 0
torch.testing.assert_close((p * nonnegative_estimator).sum(), kl)
print("逐项 log 差：", sample_difference, "完整 KL：", kl.item())
```

这里按 p 对全部候选精确加权，所以两种数值表达式的期望一致。若把 p 当作可训练变量，权重 p 自身也参与导数；只拿固定采样结果反向，不会自动得到这份完整求和的全部梯度。

因此读 PPO/GRPO 的 KL 项时，要同时标明：从谁采样、哪些概率 detach、按什么 mask 和长度平均，而不是只核对一个标量非负。

## 7. DPO：相对偏好差的差

设 chosen/rejected 的汇总 log probability 为：

```text
Policy：    -1 / -2 -> 差值 1
Reference： -2 / -2 -> 差值 0
相对提升 delta = 1-0 = 1
loss = -logsigmoid(beta*delta)
```

beta=0.1 时 loss≈0.644397。Policy 和 Reference 相同则 delta=0、loss≈0.693147。

原始序列 DPO 通常使用 token log probability 之和，本仓库使用按 mask 长度平均后的分数。取平均是改变目标，不应把它写成整句 log probability 的等式。详见 [DPO](8.DPO.md)。

### 概率乘积、log 概率和、平均分各是什么

两个动作的条件概率为 0.5 和 0.25，整段轨迹概率为 `0.5×0.25=0.125`。取 log 后：

```text
log(0.125) = log(0.5) + log(0.25)
平均 logp = (log(0.5) + log(0.25))/2
exp(平均 logp) = sqrt(0.125)，不是 0.125
```

平均 logp 对应各条件概率的几何平均，不是整段回答概率。这就是为什么 DPO 的长度平均会改变目标，为什么 PPO 抽取动作 logp 时不能先随意平均，再说仍在逐动作计算 ratio。

## 8. GRPO：先分组，再理解 detach

奖励 `[1,2,3]` 在同题组内标准化为约 `[-1,0,1]`。当前代码还做全 batch 再标准化，因此要按阶段比较变量。

```python
x = torch.tensor([-0.5], requires_grad=True)
ratio = torch.exp(x - x.detach())  # 数值为 1
ratio.sum().backward()            # x.grad 为 1
```

detach 项在这次计算图里视为常数，因此有梯度。用这个表达式不等于存储了旧策略概率；当前 GRPO 入口也没有第 3 节那样的历史比率裁剪。

### 统一比较三种优势来源

| 方法 | 主要比较基准 | 一份回答提供什么监督 |
| --- | --- | --- |
| PPO | Critic 估计与 GAE | 各动作位置的优势 |
| GRPO | 同题其他回答的分数 | 回答级相对优势广播到 token |
| DPO | chosen/rejected 与 Reference 的差 | 成对偏好损失，不先算同类 GAE |

它们都可能使用 Reference，但不能因为都出现 log probability 就把目标视为同一个。

### 推导练习的完成标准

选一个三步回答，自己标出状态、动作、奖励、value、done 与 mask；手算 delta 与 A；再用真实 GAE 核对。最后保持这条轨迹不变，只改变新策略的 logp，判断正负优势如何影响 loss。

如果改变 mask、奖励、分组、分母和温度五件事，数值即使变化也难以解释。每个实验保留一个清晰变量，并记录它对应理论公式还是当前入口实现。
