# 6. LoRA：固定原机器，增加一条可调的小分支

前置：[SFT](5.SFT.md)。LoRA 是 **Low-Rank Adaptation，低秩适配**。本章解释 [model_lora.py](../model/model_lora.py) 与 [train_lora.py](../trainer/train_lora.py) 的实际行为。

## 本章实践卡

LoRA 不改变题目，主要改变“哪些旋钮能被调整”。先运行：

```bash
.venv/bin/python scripts/lesson_lab.py --lesson lora
```

然后比较三件事：注入前后初始 logits、基础 W 的变化、LoRA B 的变化。完成 SFT 权重后，再用本章的 `train_lora` 命令训练；推理时使用 `--lora_path` 指向独立附件。

完成标准：能写出 `W`、`A`、`B` 的形状，解释 B 零初始化为什么让初始输出不变，并区分“附件文件很小”和“完整模型推理仍需要基础权重”。

## 1. 想象给一台固定机器加一个可调附件

全量微调会改原矩阵 W；LoRA 保留 W，旁边增加两个更小的矩阵 A、B：

```text
                固定 W
输入 x ────────────────> 原输出 ─┐
       └─ A：压到 r 维 ─ B：升回输出维 ─┤相加 -> y
```

数学为 `y = Wx + BAx`。附件不是一整张自由的大矩阵，而是通过窄通道 r 表达增量，这就是低秩约束。

它改变“哪些参数训练”，不强制改变“用什么数据训练”。本项目 LoRA 入口复用 SFTDataset，所以可以理解为“用 SFT 任务训练 LoRA 分支”。

## 2. 用一张 128×128 矩阵数参数

设 W 为 `[128,128]`、rank=16：

```text
全量 W：128×128 = 16384 个参数
A：16×128 = 2048
B：128×16 = 2048
LoRA 增量：4096 个参数
```

这是该层的参数比较，不是整个模型压缩成原来的四分之一。原 W 仍需要加载，激活和模型前向仍占内存；减少的主要是可训练参数及相关梯度、优化器状态。

本项目 `apply_lora()` 只为方阵 `nn.Linear` 注入。128 维、两层配置中主要是 q_proj 与 o_proj，共四处，rank=16 时合计 16384 个 LoRA 参数。它不等于“所有线性层都注入”，也未实现论文/其他库常见的 alpha/r 缩放选项。

### 用当前 63 个位置写完整行列

源码 A、B 都是 Linear，保存形状分别是 `[16,128]`、`[128,16]`。按行向量排列时：

```text
基础支路：(63×128) @ W.T(128×128) = 63×128
附件 A：  (63×128) @ A.T(128×16)  = 63×16
附件 B：  (63×16)  @ B.T(16×128)  = 63×128
相加：    两份 63×128 -> [1,63,128]
```

书上的列向量写法 `BAx`，对应这里的 `x @ A.T @ B.T`。矩阵顺序不是随便交换；先经过 rank=16 的窄通道，才恢复输出宽度。

rank 表示增量最多能通过多少个独立中间方向，不是只更新 W 的前 16 行。原 W 与全部输出特征都仍参与前向。

## 3. B 为什么全零初始化

```python
A.weight  # 小随机数
B.weight  # 全零
```

因此初始 `B(A(x))=0`，注入后输出等于原模型输出：

```text
初始：Wx + 0 = Wx
```

这样可以从基础模型原有行为开始，再学习增量。B 已经是零时，第一次反向中 A 分支的梯度可以为零，而 B 的梯度非零；B 更新后，A 才会在后续反向获得相应梯度。这不表示 A 被冻结或注入失败。

### 用真实模块检查第一次梯度

```python
# doc-example: lora-matrices
import torch
from model.model_lora import LoRA

torch.manual_seed(42)
branch = LoRA(128, 128, rank=16)
x = torch.randn(1, 63, 128)
out = branch(x)
assert tuple(branch.A.weight.shape) == (16, 128)
assert tuple(branch.B.weight.shape) == (128, 16)
assert torch.count_nonzero(out).item() == 0
out.sum().backward()
assert torch.count_nonzero(branch.A.weight.grad).item() == 0
assert branch.B.weight.grad.norm().item() > 0
optimizer = torch.optim.SGD(branch.parameters(), lr=0.01)
optimizer.step()
optimizer.zero_grad(set_to_none=True)
branch(x).sum().backward()
assert branch.A.weight.grad.norm().item() > 0
print("B 零初始化：首轮 B 获得梯度，更新后 A 也获得梯度")
```

本段单独检查分支导数，不把 `out.sum()` 当成语言模型训练目标；真实 next-token loss 的更新由本章 `--lesson lora` 验证。

## 4. 仅仅注入，还没有冻结基础模型

`apply_lora(model)` 修改 forward 为“原输出 + 低秩分支”。训练入口还必须：

```python
for name, parameter in model.named_parameters():
    parameter.requires_grad_("lora" in name)

optimizer = AdamW(
    [p for p in model.parameters() if p.requires_grad],
    lr=learning_rate,
)
```

冻结控制是否为参数累计梯度，优化器参数列表控制更新谁。不要只在模块树里看见 `lora` 就认定 W 已冻结。

### 冻结参数为什么仍然要计算基础支路

基础 W 不更新，但 `x @ W.T` 仍决定输出，而且输入 x 也可能来自可训练的上游模块。冻结是优化范围的选择，不是把基础网络从前向里删掉。

本项目冻结规则按参数名中的 `lora` 匹配，应打印实际可训练列表，不能只凭某个目录名或文件很小来判断。

`apply_lora()` 使用默认参数绑定 `original_forward` 与新分支，保证每个新 forward 对应自己的 Linear。它不是用同一份 A/B 给所有投影共享；不同注入位置分别学习。

## 6. 接已有 SFT 权重做真实训练

前一章真实 SFT 命令产生 `out/debug_accum/full_sft_128.pth` 后：

```bash
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 .venv/bin/python -m trainer.train_lora \
  --device cpu --dtype float32 \
  --hidden_size 128 --num_hidden_layers 2 \
  --data_path dataset/demo_sft.jsonl \
  --weight_dir out/debug_accum --from_weight full_sft \
  --save_dir out/lora_lesson --checkpoint_dir checkpoints/lora_lesson \
  --from_resume 0 --epochs 1 --batch_size 1 --num_workers 0 \
  --max_seq_len 128 --max_steps 2 --log_interval 1 --save_interval 1
```

`weight_dir` 是基础权重目录，`save_dir` 是附件输出目录。基础权重、tokenizer、rank 和注入位置必须与加载时一致。

`save_lora()` 保存低秩参数，不能把这个小文件直接当完整语言模型使用。推理时先创建并加载相同基础模型，再注入相同 rank 的分支并加载 LoRA 权重。完整 512 维命令见 [一天跑通](0.一天跑通.md)。

本课基础权重和附件在不同目录，使用显式附件路径完成加载：

```bash
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 .venv/bin/python eval_llm.py \
  --device cpu --save_dir out/debug_accum --weight full_sft \
  --hidden_size 128 --num_hidden_layers 2 \
  --lora_path out/lora_lesson/lora_identity_128.pth \
  --max_new_tokens 16 --prompt "What is MiniMind?"
```

`--lora_path` 可以是绝对路径，也可以相对项目根目录，适用于原生 MiniMind 加载方式。它与 `--lora_weight` 不能同时使用；原来的 `--lora_weight lora_identity` 仍会在基础模型目录下的 `lora/` 子目录查找附件。无需为了推理移动或复制附件文件。

先不带 LoRA 跑一次基础模型，再带相同附件运行，核对加载流程。短训后文本可能相同或混乱，不能只凭一次采样判断附件是否生效；小实验已通过直接比较参数验证基础 W 不变、B 更新。

## 7. 保存时为什么有两种文件

```text
out/lora_lesson/lora_identity_128.pth：只含 LoRA 附件参数
checkpoints/lora_lesson/*_resume.pth：当前实现保存完整模型和续训状态
```

所以“LoRA 推理附件很小”不等于“本项目所有续训文件也都很小”。`load_lora()` 还会剥掉模块路径前缀，让内部 `A.weight/B.weight` 匹配。

完成标准：能写出原 W 和 A/B 的形状，指出哪些参数有 requires_grad，并用一次实际更新证明基础权重没变。下一步可选择 [DPO](8.DPO.md)，比较“换损失”和“换更新范围”的区别。

### 保存、重载与合并的区别

附件存的是 A/B，不是 `W+BA` 的整张矩阵。若要在数学上合并，本实现无额外缩放时为：

```text
ΔW = B @ A：(128×16) @ (16×128) = 128×128
W_merged = W + ΔW
```

当前 `save_lora()` 没有执行这个合并。若外部手动合并后又保留同一个附件支路，前向会重复加增量。先理解文件与前向，再研究部署合并。

调试顺序：查看注入的四个模块 → 列出 requires_grad=True 的参数 → backward 后看 A/B → step 前后比较基础 W → 重载同一基础版本与附件。附件相同而基础 W 不同，也不是同一模型。

自查：rank 从 16 改为 8，该层附件参数变成 `8×128+128×8=2048`，但基础 W 仍有 16384 项；文件更小不能说明表达能力或任务效果一定更好。

## 8. 真正保存一次附件，再用另一实例重载

模块树里看到 LoRA，只能证明注入过；要证明保存文件可用，应创建另一实例，加载同一基础参数与附件，再比较固定输入的 logits。

本例使用实际 SFT 样本和随机小模型，执行一次回答监督更新。基础参数副本只保留在内存，附件写临时目录并清理；不覆盖已有模型。

```python
# doc-example: lora-save-reload
from pathlib import Path
from tempfile import TemporaryDirectory
import torch
import torch.nn.functional as F
from dataset.lm_dataset import SFTDataset
from scripts.lesson_lab import tokenizer, small_model
from model.model_lora import apply_lora, save_lora, load_lora
from trainer.train_utils import setup_seed

torch.set_num_threads(2)
setup_seed(42)
tok = tokenizer()
dataset = SFTDataset("dataset/demo_sft.jsonl", tok, max_length=128)
X, Y, mask = (t.unsqueeze(0) for t in dataset[0])
model = small_model()
base_state = {name: p.detach().clone() for name, p in model.state_dict().items()}
apply_lora(model, rank=16)
for name, parameter in model.named_parameters():
    parameter.requires_grad_("lora" in name)
trainable = [p for p in model.parameters() if p.requires_grad]
assert sum(p.numel() for p in trainable) == 16_384
optimizer = torch.optim.AdamW(trainable, lr=1e-3)
logits = model(X).logits
per_token = F.cross_entropy(logits.flatten(0, 1), Y.flatten(), reduction="none").view_as(Y)
loss = (per_token * mask).sum() / mask.sum()
loss.backward()
optimizer.step()
torch.testing.assert_close(
    model.model.layers[0].self_attn.q_proj.weight,
    base_state["model.layers.0.self_attn.q_proj.weight"], rtol=0, atol=0,
)
with torch.no_grad():
    expected = model(X).logits
with TemporaryDirectory(prefix="lora_roundtrip_") as directory:
    path = Path(directory) / "adapter.pth"
    save_lora(model, path)
    restored = small_model()
    restored.load_state_dict(base_state)
    apply_lora(restored, rank=16)
    load_lora(restored, path)
    with torch.no_grad():
        actual = restored(X).logits
    torch.testing.assert_close(actual, expected, rtol=0, atol=0)
print("SFT 更新只改附件；同基础权重+同附件重载后 logits 完全一致")
```

`base_state` 必须在注入和更新前保存，否则可能把不同基础版本混入对照。新建实例的随机初始化不重要，因为完整基础参数随后由同一份 state 覆盖。

### 从梯度形状看 A/B 如何共同调整

令中间量 `u=x @ A.T`，低秩输出 `d=u @ B.T`，N=63：

```text
x：N×128
u：N×16
上游 d_d：N×128

d_B = d_d.T @ u：(128×N) @ (N×16) = 128×16
d_u = d_d @ B：  (N×128) @ (128×16) = N×16
d_A = d_u.T @ x：(16×N) @ (N×128) = 16×128
```

当 B 为零，d_u 也为零，所以首轮 d_A 可以全零；d_B 仍取决于 u 和上游反馈。这比“一个先学，一个后学”的口头说法更具体：次序来自当前初始化与链式求导。

### 重载不一致，按四个条件排查

| 条件 | 不一致会怎样 |
| --- | --- |
| 基础 W 相同 | 否则原支路已不同 |
| rank 相同 | 否则 A/B 形状冲突 |
| 注入位置相同 | 否则 key 或前向支路不匹配 |
| tokenizer 与模板相同 | 否则同样文字可能形成不同输入 |

附件的“大小”只是存储事实；是否生效以参数加载与固定输入对照为证据，是否有用以任务表现为证据。
